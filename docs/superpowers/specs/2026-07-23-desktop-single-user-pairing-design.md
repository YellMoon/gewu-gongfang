# 桌面端单人模式、一次性配对与手动同步设计

日期：2026-07-23
状态：方案已口头确认，等待书面规格复核

## 1. 背景与目标

当前微信小程序为个人主体，无法稳定取得手机号，因此依赖微信手机号证明的桌面首次注册、密码重设和数据主机初始化暂时不可用。现阶段桌面端只有同一位实际使用者，目标是在不削弱数据主机边界、不把长期密钥打进安装包、不让普通电脑自行成为数据主机的前提下，恢复可用的桌面身份与同步链路。

本阶段采用“主机本地建立身份 + 一次性配对普通设备 + 用户手动发起同步、主机自动批准”的临时单人模式。微信小程序及其现有身份架构冻结，待小程序变更为具备手机号能力的企业/非个人主体后再恢复完整的人类身份核验。

## 2. 范围与非目标

本阶段包含：

- 当前数据主机在本机完成单人模式初始化、设置或重设本机密码；
- 数据主机生成短时、一次性配对码，授权一台普通桌面端；
- 普通端手动点击同步，先看预览，再确认提交；数据主机在线时自动处理；
- 配对、同步、备份、冲突、撤销和模式切换的审计与恢复；
- 普通版与数据主机版桌面安装包继续物理隔离；
- 当前版本完成后发布普通端与数据主机端 OSS 更新，并按用户要求把安装包上传夸克网盘。

本阶段不包含：

- 不改动、不重新上传、不发布微信小程序；
- 不新增短信、共享口令、匿名账号或安装包内置密钥作为身份替代；
- 不允许后台静默同步；
- 不允许普通端初始化、迁移、恢复或接管数据主机；
- 不自动解决业务冲突，不因自动批准而覆盖数据主机中的较新内容；
- 不废弃现有 canonical 用户、角色、设备签名、V2 桌面会话或主机 epoch 模型。

## 3. 配置与模式边界

新增受控配置 `GEWU_DESKTOP_IDENTITY_MODE`，只接受：

- `full`：完整身份模式，也是代码、打包和新部署的默认值；
- `single-user`：临时单人模式，只能由数据主机部署配置显式启用。

普通桌面安装包不携带可改变该配置的界面、环境值或长期凭证。运行时还必须同时满足不可变构建身份 `nodeRole=primary-host`，才可暴露单人模式初始化和配对码签发接口。云端配置不能把普通版提升为数据主机版。

该配置以当前数据主机本地运行时为权威。云网关可始终理解并转发配对协议，但只有收到当前主机 epoch 签名的在线能力声明后才显示“主机可配对”；网关自身没有开启单人模式或签发授权的权限。

现有 canonical 超级管理员记录继续作为唯一 owner。单人模式只增加一种临时认证来源，不创建任意新用户，也不改写角色模型。

## 4. 数据主机本地初始化

仅数据主机版、仅回环地址/受信任 Electron IPC、且 `GEWU_DESKTOP_IDENTITY_MODE=single-user` 时可以发起初始化。服务按以下顺序执行：

1. 确认构建身份为 `primary-host`，并校验设备私钥可用；
2. 对本地 SQLite 执行 `quick_check`、必需表/版本检查，确认唯一 canonical 超级管理员；
3. 校验题库盘绑定、存储标识和可写性；
4. 在任何身份状态变更前创建数据库备份和题库元数据清单；
5. 要求用户在主机窗口内二次确认并设置本机密码；密码使用项目现有强 KDF 存储，明文不落盘、不写日志；
6. 原子建立或绑定当前主机 epoch、owner、主机设备授权与凭证版本；
7. 写入 `single_user_host_bootstrap` 审计记录和备份引用。

本地认证来源标记为 `single_user_local_bootstrap`。如果已经存在有效主机 epoch，则初始化不能隐式覆盖它。重设本机密码只轮换本机解锁凭据及相应凭证版本，不修改业务数据、题库盘内容、canonical 用户、设备 ID 或同步历史。涉及主机迁移/恢复时仍使用专用受保护流程，单人模式不提供捷径。

## 5. 一次性配对授权

### 5.1 签发

配对码只能由已用本机密码解锁的数据主机窗口生成。它必须：

- 由密码学安全随机源生成 80 bit 随机值，使用排除易混淆字符的 Crockford Base32 编码为 16 个字符，并按 `XXXX-XXXX-XXXX-XXXX` 显示；
- 默认 10 分钟过期，只能成功使用一次；
- 服务端只保存带独立 salt 的摘要，不保存或回显历史明文；
- 绑定当前 owner、主机 epoch、generation、用途 `ordinary-desktop-pairing`；
- 支持主机主动撤销；
- 限制失败尝试次数，并按配对码、设备与来源地址限速。

### 5.2 普通端申请

普通端首次打开身份页时先在本机生成设备私钥并存入操作系统安全凭据存储，再提交：配对码、设备 ID、用户可读设备名、公钥、指纹和协议版本。私钥永不离开本机。

直连和云中继都遵守同一信任判定：云网关只能暂存/转发配对请求，不能自行把请求升级为授权。数据主机必须在线，核对 epoch、generation、配对码摘要、尝试次数和设备指纹，并在一个事务内完成“消费配对码 + 创建设备授权”。并发使用同一码时只能有一个请求成功。

成功后复用现有 `desktop_device_authorizations`、设备签名和 V2 短时桌面会话设施，授权来源明确记录为 `single_user_pairing`。只签发普通桌面权限；申请中即使伪造 `primary-host` 角色也必须被拒绝。

## 6. 同步行为

配对成功不触发同步。普通端同步页保留人工操作：

1. 用户点击“开始同步”；
2. 客户端通过设备签名换取短时 V2 桌面会话；
3. 计算并展示上传、下载、删除、冲突和拒绝项预览；
4. 用户确认后才提交同步批次；
5. 数据主机在线时自动领取并处理有效批次，不再出现“申请同步权限/等待微信或人工批准”；
6. 返回应用结果、冲突和可恢复信息。

自动批准只省略人工审批，不改变权限校验、数据范围、删除保护、来源追踪或冲突策略。冲突项保持待处理并在界面可见；客户端队列只有在收到主机明确成功回执后才能移除。

## 7. 数据安全、备份与事务

每个非空同步批次在写入主机前都必须经过只读预检：会话/设备状态、actor、schema 版本、表白名单、字段范围、删除权限、题库盘状态和批次幂等键。

写入前创建：

- SQLite 在线备份；
- 受影响题库文件与元数据清单（路径、摘要、版本，不复制无关题库内容）；
- 将两者关联到本次批次的 backup ID。

数据库变更在单一事务中提交。题库文件继续通过既有可信存储服务写入；若文件阶段失败，数据库事务不得提交，失败批次和客户端队列保留，备份与失败审计不删除。对于无法用单一数据库事务覆盖的外部文件替换，先写临时文件并校验摘要，再原子替换；替换失败时保留原文件并标记人工恢复，不宣称同步成功。

审计至少记录：来源设备、owner、会话/请求/批次 ID、变更摘要与按表/新增/修改/删除计数、冲突/拒绝数、backup ID、主机 epoch/generation、结果和错误码。审计不记录配对码、密码、私钥、会话 token 或业务数据原文。

## 8. 撤销、模式关闭与恢复完整身份

关闭 `single-user` 后立即执行以下规则：

- 拒绝签发和消费新的单人配对码；
- 撤销来源为 `single_user_pairing` 的所有普通设备授权，并递增相应凭证版本，使既有会话失效；
- 禁止 `single_user_local_bootstrap` 继续签发主机会话；已有本机密码散列保留但在完整身份模式下不再接受，直至完成完整身份重新核验；
- 失效未消费的配对码和待处理的单人配对请求；
- 保留所有业务数据、题库、备份、审计、设备记录和主机 epoch；
- 数据主机不会自动降级或丢失主机身份，但在完整身份模式下，后续敏感操作必须重新通过恢复后的完整人类身份核验。

管理员可在数据主机设备中心逐台撤销普通设备。设备撤销后，本地离线改动不删除；设备重新取得合法授权后仍需预览和确认，才能再次提交。

## 9. 用户界面

数据主机身份页在单人模式下显示“单人模式初始化/重新核验并重设密码”，明确说明重设密码不删除本机数据、不改变同步数据，只会使旧解锁凭据失效。验证完成后进入设备中心，可生成、复制和撤销一次性配对码，并显示剩余有效时间。

普通端身份页显示设备名与配对码输入，不显示数据主机初始化、迁移或恢复入口。配对成功后设置该电脑自己的本机解锁密码。同步页将旧的“申请权限”文案改为“开始同步”，预览确认界面沿用现有结构并补足冲突、拒绝与备份结果。

Electron 窗口隐藏默认 `File / Edit / View / Window / Help` 应用菜单；保留开发调试快捷键仅限开发构建。OSS 更新检查、下载和安装入口必须在普通版与数据主机版都可见，但两种 flavor 使用各自隔离的 feed。

## 10. 错误处理

界面必须为以下情形提供明确中文错误和下一步：配对码过期、已使用或被撤销；尝试次数过多；主机离线；主机 epoch/generation 已变化；设备 ID/公钥指纹冲突；本机安全存储不可用；数据库或题库预检失败；备份失败；同步冲突；单人模式已关闭。

错误消息不得直接显示底层 IPC/remote method 堆栈。可安全重试的错误保留输入和本地队列；安全边界错误清除短时会话，但不删除业务数据。

## 11. 测试与验收

实现采用测试先行，至少覆盖：

- 单人模式配置默认关闭、枚举校验、普通 flavor 无法启用；
- 主机初始化的本地通道限制、DB/题库/私钥预检、备份先于变更、密码重设不改业务数据；
- 配对码熵、摘要存储、过期、撤销、一次性并发消费、失败次数和限速；
- 云网关不能独立授权、主机离线不成功、直连与中继产生相同授权；
- 普通设备不能获得主机 bootstrap/transfer/recovery 权限；
- 手动预览/确认、主机自动处理、幂等重试、冲突保留、失败队列不丢失；
- 单人模式关闭后会话和配对授权失效但业务数据、主机 epoch 与审计保留；
- 默认菜单消失、密码重设和配对 UI、同步文案、OSS 更新入口的 UI 回归；
- 后端、桌面、云网关全套测试，生产构建，Electron 真实运行时，Node/Electron native ABI 恢复。

真实验收必须分别记录数据主机与普通端：首次初始化/配对、重启后本机解锁、同步预览、自动批准、冲突/离线错误、设备撤销、OSS 检查更新。不能仅凭单元测试声明完成。

## 12. 发布与回滚

发布顺序：

1. 检查当前工作树和此前 PR/提交，保留所有现有改动；
2. 阿里云数据库与代码备份，部署兼容旧客户端的后端/网关，运行内外网健康和权限契约检查；
3. 当前数据主机本地备份，安装数据主机 flavor，保留数据目录、题库盘绑定和设备配置并做真实验证；
4. 构建普通端与数据主机端安装包，递增版本，发布各自 OSS feed 并验证 `latest.yml` 与安装包摘要；
5. 普通端只通过 OSS 自助更新，不逐台安装；
6. 按本次用户明确要求，将最终安装包上传夸克网盘并核验；
7. 微信小程序标记为“本阶段冻结/不适用”，不构建、不上传、不宣称发布完成；
8. 复核此前任务（OSS 更新模块、窗口菜单、密码重设、体系功能、数据主机 flavor 隔离等）的代码、测试和发布证据，缺失项纳入同一收尾清单；
9. 全部验证通过后提交并合并/推送 `gewu/master`。

回滚时优先关闭 `GEWU_DESKTOP_IDENTITY_MODE=single-user` 并撤销该来源授权，再回退应用版本；不得删除业务数据库。同步数据异常按 batch 对应的 SQLite 备份、题库清单和审计记录恢复。任何端版本或外部上传未完成时，只能报告“部分发布”或“受阻”。

## 13. 关键不变量

- 安装包和渲染进程中没有长期同步密钥；
- 普通端永远不能把自己提升为数据主机；
- 配对码一次性、短时、摘要存储，由在线数据主机最终裁决；
- 同步永远由用户手动发起，自动批准不等于自动覆盖冲突；
- 密码重设与设备撤销不删除业务数据；
- 关闭临时模式后，临时授权全部失效，数据和审计完整保留；
- 微信小程序保持冻结，直到用户明确恢复企业主体相关工作。
