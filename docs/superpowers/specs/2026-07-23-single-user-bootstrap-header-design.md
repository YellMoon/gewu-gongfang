# 单人数据主机初始化与身份页标题设计

日期：2026-07-23  
状态：已获用户口头确认，待规格复核后实施

## 目标

修复数据主机专用桌面端在单人模式初始化时把设备身份错误生成为
`desktop-client`、从而被本地后端拒绝的问题；同时精简身份验证卡片的顶部层级。

## 行为设计

### 数据主机 bootstrap

- 数据主机专用构建处于 `single-user` 模式且尚未完成 bootstrap 时，
  `begin-single-user-enrollment` 必须生成 `primary-host` 类型的公开设备身份。
- 普通桌面端和普通身份注册继续生成 `desktop-client`，不得借此获得数据主机能力。
- 设备类型由 Electron 主进程根据可信构建类型与受管运行模式决定，不接受渲染进程传入的
  `deviceKind` 作为授权依据。
- 后端继续严格要求 bootstrap 身份类型为 `primary-host`，不放宽现有校验。
- 失败发生在写入前时，不创建主机 epoch、主机凭证或桌面身份保险库。

### 身份验证卡片标题

- 删除“同一个人可以同时拥有超级管理员和老师身份；每台电脑分别注册、分别撤销。”
  及其占位空间，不显示替代文案。
- 将现有蓝色盾牌图标和“格物工坊身份验证”标题放在同一横向标题栏中，
  左对齐、垂直居中。
- 标题栏与后续步骤内容之间保留分隔线；表单随说明文字删除而自然上移。
- 窄窗口下仍保持清晰层级，允许适度缩小图标、字号和间距，不产生裁切或重叠。
- 盾牌仅作装饰，不改变标题的可访问名称与语义层级。

## 错误与恢复

- 对 `DESKTOP_SINGLE_USER_DEVICE_KIND_INVALID` 提供明确的本地化错误说明，
  避免仅显示“身份验证未完成，请重试”。
- 修复后重新提交初始化时，沿用当前待初始化状态；用户重新输入密码即可，
  不需要删除数据库、题库或运行配置。
- bootstrap 成功后必须通过主机专用 preload 桥接重启，并在重启后验证 epoch、
  主机凭证、身份保险库与原数据路径。

## 验证

- 先增加失败测试，证明数据主机单人初始化必须生成 `primary-host`，且普通桌面注册不变。
- 增加界面回归检查：旧说明文案不存在，图标与标题位于同一标题容器。
- 运行桌面身份、主机运行时、类型检查及相关完整测试。
- 在真实 Electron 运行时执行一次 bootstrap：
  - 提交前数据库、题库绑定与数据计数不变；
  - 提交后生成 active epoch、主机凭证与身份保险库；
  - 重启后可使用本机密码进入；
  - 窗口无设备码、无旧说明文案，标题横向布局无重叠。

## 非目标

- 不改变超级管理员、老师等角色能力及角色切换规则。
- 不放宽普通桌面端的数据主机权限。
- 不改变微信小程序登录与权限架构。
- 本轮真实运行时与统一矩阵验证完成前不推送、不打包、不部署。

## 回滚与发布

- 代码回滚只需恢复 Electron 设备类型选择和身份卡片头部结构；业务数据库无需回滚。
- 若真实 bootstrap 未通过，保留现有备份和运行配置，停止发布并继续诊断。
- 只有统一多端矩阵通过后，才进入版本递增、桌面安装包、OSS 与其他既定发布步骤。
