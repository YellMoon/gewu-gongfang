# 题库公式全链路与所见即所得编辑设计

## 目标

将题库的 Word 导入、试题编辑、组卷导出统一到一条可验证的数据链路：正文和批注中的 Word 自带公式、EQ 域代码及 MathType OLE 均被完整提取并转换为规范化 LaTeX；题干、选项、小题、答案和解析在桌面端以所见即所得方式编辑；本地数据主机按每次组卷选择输出 Word 自带公式、EQ 域、MathType 兼容公式或 LaTeX 矢量公式。

所有输出公式必须是可见的排版结果。任何 LaTeX、MathML、OMML XML、EQ 指令或其他底层代码都不得作为输出文档中的可见兜底。

## 已确认的边界

- 本地数据主机保存权威题库，并独占 Word/PDF 组卷生成任务。
- 其他桌面端负责离线录入、解析、编辑和经授权同步；小程序和其他桌面端只提交组卷参数、查看进度并下载结果。
- 编辑时只修改规范化 LaTeX，不同步维护四套公式格式。
- 原始 OMML、EQ、MathType OLE及预览用于追溯、重新转换和视觉兜底，不是编辑主数据。
- 不依赖破解 MathType。MathType 输出采用经代码审计和真实 Word 验证的开放格式生成器；若不可靠则回退到可见矢量结果。
- 输出后不要求仍能在 MathType 中编辑，完整显示和稳定排版优先。

## 总体架构

### 统一内容遍历器

用同一套 WordprocessingML 内容遍历逻辑处理 `word/document.xml` 和 `word/comments.xml`。遍历器接收当前 part、关系表和上下文，按文档顺序产生文本、样式、公式、图片、换行和表格标记。正文与批注仅在归属信息和关系文件路径上不同，不再各自维护能力不一致的解析函数。

公式识别覆盖：

- OMML：`m:oMath`、`m:oMathPara` 及常见复杂节点。
- EQ 域：`w:fldSimple@w:instr` 与由 `fldChar begin/separate/end` 包围、可跨多个 run 的 `w:instrText`。
- MathType：`o:OLEObject`、关联 embedding、ProgID、VML/Drawing 预览及显示尺寸。
- 表格、正文、批注中的行内和独立公式。

遍历结果保留 part、段落、批注 ID、关系 ID、内容序号和原始载荷哈希，使每个公式可追溯。

### 统一公式模型

`FormulaDocument` 包含：

- `id`：稳定标识。
- `canonicalLatex`：唯一可编辑主格式。
- `normalizedMathml`：转换中间格式，可按需重建。
- `displayMode`：行内或独立。
- `typography`：字号、颜色、基线、原始尺寸等显示信息。
- `sourceFormat`：OMML、EQ、MathType 或用户创建。
- `sourcePayload`：原始 XML、域指令、OLE/预览引用。
- `conversionStatus` 与 `warnings`：完整、近似、待校正或仅预览。
- `edited`：用户编辑后以 LaTeX 为权威，不再使用原始语义对象覆盖内容。

富文本内容以结构化 JSON 保存，文字节点承载字体、字号、粗体、斜体、下划线、删除线、颜色、对齐、缩进、行距、列表及上下标；公式节点引用 `FormulaDocument`；图片节点保存资源引用、尺寸、对齐和替代文本。HTML仅作为兼容读写边界，不作为无约束的权威存储。

### 转换链路

- OMML 经完整节点转换器生成 LaTeX，并以 MathML/渲染结果交叉验证。
- EQ 域先构建完整字段状态机，再把分式、根式、上下标、积分、求和、括号、矩阵等支持子集转换为 LaTeX；无法可靠解释的域保留原可见结果和警告。
- MathType OLE 复用 D 盘参考项目的批量 Ruby `mathtype_to_mathml_plus` 链路，按内容哈希缓存 MathML，再转换为规范化 LaTeX。
- 转换器必须隔离单公式失败，不能吞掉整个文档异常；错误进入质量报告。

## 所见即所得编辑器

### 产品方向

- 客户端：Windows/Electron 桌面生产力工具。
- 角色：教师长期使用的教学内容生产画布。
- 方向：专业、安静、可信、键盘友好；均衡且任务导向的密度。
- 层级：题目结构导航与保存状态安静存在，编辑画布是第一视觉层，格式工具栏随选择提供即时反馈。
- 视觉系统：中性浅色画布、清晰边界、有限阴影、单一主操作色、状态色只表示状态；不使用营销卡片、装饰渐变或无关动效。
- 动效预算：仅用于焦点、弹层和保存反馈，并遵守减少动态效果偏好。

### 编辑行为

编辑器覆盖题干、选项、小题、答案和解析，并统一使用相同编辑内核。常用行为包括：

- 撤销/重做、格式刷或清除格式。
- 字体、字号、粗体、斜体、下划线、删除线、文字颜色和背景色。
- 左/中/右/两端对齐、行距、段前段后、缩进、项目符号和编号。
- 上标、下标、软换行、分页提示、链接和特殊符号。
- 行内/独立公式插入，公式弹层提供可视预览、LaTeX输入、常见物理与数学模板、校验和键盘确认。
- 图片插入、粘贴、拖放、缩放、对齐、替代文本和删除。
- 选项增删、排序、正确答案标记；小题增删、排序及独立答案。
- 粘贴 Word 内容时清理危险样式，同时保留允许的文本格式、公式和图片。
- 完整键盘操作、可见焦点、逻辑 Tab 顺序、工具栏 ARIA状态和保存失败恢复。

桌面宽度使用固定工具栏和单一主画布；窄窗口折叠低频工具但不缩小主要输入字号。所有按钮必须对应真实命令。

## 集中导出

导出请求保存公式首选格式、答案位置、纸张、页边距、字号、行距和图片策略。数据主机从权威快照生成不可变任务输入，避免导出期间题目被修改。

四种首选格式：

- Word 自带公式：LaTeX/MathML 转 OMML。
- EQ 域：转换支持子集并提供已更新的可见字段结果。
- MathType：生成 MathType兼容 MTEF/OLE，并附带自有可见预览；不以可编辑性作为完成条件。
- LaTeX：用排版引擎生成 SVG，必要时生成 EMF/高分辨率透明 PNG，并嵌入 LaTeX 元数据供格物工坊重导入。

### 显示优先回退

每个公式独立执行：

1. 尝试用户首选格式，并验证结构与预览。
2. 使用导入时保存且仍与权威 LaTeX一致的原始可见对象或预览。
3. 生成统一 LaTeX SVG/EMF。
4. 生成高分辨率透明 PNG。
5. 若仍无可见结果，阻止导出并列出题号、内容位置和失败原因。

不得输出源码、空白占位或已知错乱的公式对象。导出质量报告记录实际采用格式和回退次数，但不把调试信息写进试卷正文。

## 数据主机任务与多端契约

- 小程序及非主机桌面端只创建导出任务并轮询状态。
- 云端只保存任务元数据、状态和产物地址，不成为题库权威源。
- 数据主机领取任务后校验权限、题目版本和资源完整性，生成 DOCX/PDF并写入受控产物目录。
- 任务结果包含版本、哈希、页数、题数、公式数、实际格式分布和错误摘要。
- 任务必须支持幂等、超时、取消、失败重试和过期清理。

## 验证矩阵

解析样本至少覆盖正文/批注/表格中的 OMML、简单与复杂 EQ 域、MathType OLE，以及分式、根式、上下标、积分、求和、极限、矩阵、方程组、分段函数、矢量、重音、中文单位和图文混排。

验证分层：

- 单元测试：字段状态机、OMML/MathML/LaTeX转换、MTEF读取、内容顺序、富文本命令、导出回退。
- 集成测试：合成 DOCX和真实样本的导入、保存、重载、编辑、任务生成。
- 文档验证：四种模式生成 DOCX/PDF，用 Word/LibreOffice渲染或受控转换为页面图片，检查公式数量、裁切、基线、字号、分页和图片关系。
- UI验证：真实 Electron/浏览器运行，覆盖桌面与窄窗口、键盘、粘贴、公式编辑、图片缩放、保存错误和恢复。
- 多端验证：小程序提交任务、云端中继、主机领取、产物下载及权限契约。

## 发布与回滚

按统一版本矩阵发布。接口、数据结构和 UI变化需要桌面端、小程序、云端及本地数据主机兼容检查。数据库迁移必须可重复且保留旧字段读取兼容；原始公式载荷不得在迁移中删除。部署前备份数据库和代码，发布失败时回滚服务与桌面更新 feed。未完成微信上传、云端部署、主机升级和 OSS feed验证时只能报告部分发布。
