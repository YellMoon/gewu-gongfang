# 托管主机身份与公网中继真实验证

## 目标

普通桌面端和数据主机端在公网中继下完成真实 UI 驱动的配对、在线身份续期和双向同步，用户不接触任何云端令牌、共享密钥或内部凭据。测试必须使用独立临时主机和临时业务数据，不能读写权威业务数据。

## 已确认的问题

旧运行时配置保留了 `desktopSyncToken`。它曾同时承担云端主机认证、JWT 派生和中继断言签名，导致测试脚本把它当成必须从真实数据主机复制的共享密钥。现代主机身份已经使用主机 epoch、generation 和操作系统加密凭据库，但隔离主机的引导及 E2E 脚本没有完整使用该路径。

## 设计

1. 云端主机认证以托管主机凭据为唯一优先路径。主机凭据只保存在数据主机的操作系统加密凭据库，运行时以短期请求头发送；普通端、设置页面和测试配置均不读取或展示它。
2. 旧 `desktopSyncToken` 仅作为已部署旧主机的迁移兼容入口。它不得成为新主机、隔离测试或公网中继功能的前置条件，也不得从权威主机复制到临时档案。
3. 新增临时云测试主机引导：测试控制器创建仅含测试主机 epoch 的临时云端身份及一次性恢复/领取材料，隔离数据主机通过现有主机激活界面完成领取。该身份独立于权威主机，带自动过期和清理标记。
4. 测试以两个打包 Electron 实例的真实 UI 完成：主机激活、普通端获取云端配对能力、输入配对码、设备绑定确认、在线会话续期、普通端到主机同步、主机到普通端同步。局域网连接在云中继阶段被禁用或不可达。
5. 清理始终执行：撤销测试主机 epoch、删除临时云任务和临时业务数据、删除临时应用档案及凭据。清理失败必须记录为测试失败，不能默默遗留主机身份。

## 安全与兼容性

- 不输出令牌、主机凭据、恢复材料或权威数据路径。
- 不改变现有权威主机的 epoch、角色、同步队列或设备授权。
- 旧主机仍可通过已有兼容路径运行；迁移后新安装和测试均不依赖共享密钥。

## 验证标准

- 自动测试证明：新临时主机引导不需要 `desktopSyncToken`；云端请求使用托管主机凭据；旧兼容仅在明确旧配置时启用；清理可验证。
- 真实测试证明：两个隔离 Electron 窗口显示云中继通道、配对成功、身份设备页面在线且绑定、双方各产生一条临时变更并通过确认同步到对端。
- 回归：现有局域网、主机运行时、云中继、身份、同步和 Electron 打包契约测试通过。
