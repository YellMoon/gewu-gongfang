# 统一桌面密码身份设计

## 目标

桌面端和小程序共享同一个云端 canonical account。手机号是跨入口的唯一绑定键；桌面端可用手机号或自定义账号名加密码在线登录。新设备登录成功后仍须经过现有设备证明与云端静默登记，不能用密码跳过设备登记。

## 设计

- 新增控制面密码凭据关系，只保存账号、可选账号名、scrypt 参数、随机 salt、派生 hash、版本与时间；不保存明文密码、手机号、微信凭据或本地 vault 密钥。
- 账号名是可选的受限 ASCII 别名；没有别名时使用手机号登录。手机号输入只在云端 API 内计算 HMAC，再以 HMAC 查询已验证联系人。
- 首次设置或重置密码必须携带新的在线微信手机号证明。该证明先解析/创建 canonical account，随后原子替换该账号的凭据并递增账号 auth version，旧会话失效。
- 密码登录在线读取受限的 credential view，由云端 API 用 scrypt 恒定时间比较；成功后只签发短期 verification token，随后复用现有 `desktop.online-register` 设备证明与会话签发流程。
- 用户名、手机号或密码任一不匹配、账号/联系人撤销、凭据缺失、过期验证 token 都统一拒绝；不返回“账号是否存在”的差异，也不在日志、收据或 outbox 写入密码材料。
- 登录失败按账号/IP 进行有限窗口节流；密码更新和新设备登记均不允许离线完成。

## 权限与边界

- 只有可信 identity-verifier 可执行凭据建立、更新和受限读取函数；writer/runtime/verifier/PUBLIC 无表 DML、无凭据读取、无函数执行权。
- PostgreSQL 不自行计算密码 hash。云端可信服务使用固定 scrypt 参数与随机 salt，数据库只校验格式、账号状态与 version，并通过 SECURITY DEFINER 例程保存或返回受限记录。
- M1--M17、业务表、题库/NAS、旧 SQLite、旧人工审批和 primary-host 路径不在本切片内。

## 验证合同

1. 手机号首次设置密码后，手机或账号名都解析到同一 canonical account。
2. 错误密码、未知账号名、撤销账号、旧密码、缺失/篡改盐或 hash 均失败且不泄露存在性。
3. 重置密码使旧认证与旧在线会话失效；新密码可得到短期登记 token。
4. 密码 token 仍必须携带新设备私钥证明才能静默登记；离线无登录入口。
5. catalog/ACL、PG 事务回滚、并发账号名冲突、失败节流及 API 负向路径均有红测；最终由 disposable PG、云端和桌面客户端做端到端验证。
