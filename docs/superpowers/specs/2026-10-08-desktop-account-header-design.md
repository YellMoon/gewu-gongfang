# 桌面端个人中心与页面抬头整合方案

桌面端面向超级管理员和教师。将账号资料、登录设备和软件更新集中到“我的”，取消独立“系统参数”入口；全部页面使用统一抬头，账号控件进入正常布局，工作台只保留一个同步入口。此方案待用户确认，应用代码尚未修改。

## 我的

顶部展示姓名和当前角色，个人资料包含账号名、联系电话、微信号、任教科目。只有教师显示任教科目；可切换身份的账号继续通过既有身份切换流程切换，权限由云端裁决。

个人资料下面设置两个区域：

- 登录设备：保留现有设备名称、状态、登录时间、最近活跃时间和撤销操作，默认收起，展开后读取设备数据。
- 软件与更新：显示安装包版本和检查更新入口。发现更新后提供下载，下载完成后提供重启安装；错误直接出现在更新区域，不长期展示更新地址及实现说明。

保留旧 `identity-devices` 和 `system-params` 导航兼容映射，前者进入“我的”的设备区域，后者进入软件更新区域。导航菜单只展示一个“我的”，不出现两个内容重复的入口。

超级管理员的账号申请审核属于管理能力，使用现有权限判断，在管理区域提供；操作日志保留在管理区域。教师个人中心不展示其他账号审核内容。

## 个人资料的数据来源

现有 `desktopAuthorizationSession` 返回当前账号姓名、角色和教师关联标识。`desktopIdentityClient.profileFrom` 当前仅保留用户标识和姓名，新增资料不能只在 JSX 中写标签。

教师联系电话和科目来自云端教师档案，按当前账号实际关联的教师标识读取，不按姓名匹配。账号名来自云端登录凭据的账号名称字段，不能将内部账号标识当成账号名。

教师档案目前没有微信号字段。若支持个人微信号，需要云端资料字段、读取接口及提交流程；微信登录绑定与用户自己填写的微信号应分别呈现，不使用 OpenID 或 UnionID 充当微信号。

未返回的资料不能宣称已填写或已绑定。加载失败提供重试，离线展示最近已验证资料及必要离线提示。资料修改遵循既有云端写入和离线草稿确认规则，角色标签不作为可自由编辑字段。

## 统一页面抬头

正常窗口内，导航按钮、页面标题、必要上下文、刷新、同步和账号入口位于同一条标题栏。今日日期作为今日工作台标题旁的上下文，不再设置单独的日期卡片和泛化副标题。

账号入口显示姓名，角色和锁定、身份切换等操作归入账号菜单。点击“我的”进入个人中心。账号控件通过组件布局传递并占据真实空间，取消固定悬浮定位及按按钮数量计算的右侧避让宽度。

空间不足时有序换行，按钮不得相互覆盖。内容区域高度随真实标题栏及离线提示高度分配，不依赖固定减去 64 px 的假设。保持导航展开时不挤压工作区的原有行为。

每个页面只保留一个页面级标题。筛选条件、统计结果、编辑对象名称、试卷名称等业务内容仍保留。重复标题所在卡片内的有效按钮与数据迁入工具区域，不能通过整块隐藏误删功能。

## 今日工作台

删除独立日期抬头、重复说明、正常同步标签、云同步快捷卡片及同步正常提醒卡片。同步状态仅由全局入口负责，待提交、冲突和离线可突出显示并打开现有同步面板。

保留课程表、费用统计、题库三个真实快捷入口，调整为三个自然分布的卡片。保留今日课程、欠缴、结课余额和问题试题提醒；清理“点击仅提示，不跳转”等实现说明及题库入口的重复文案。

## 验收范围

导航类型共有 22 个状态页：`today`、`course-calendar`、`schedule-list`、`course-info`、`school`、`address`、`institution`、`question-bank-tools`、`question-bank-import`、`question-bank-preview`、`question-bank-edit`、`question-bank-paper`、`question-bank-audit`、`payment`、`revenue-statistics`、`personal-assets`、`teacher`、`student`、`identity-devices`、`system-params`、`operate-log`、`cloud-sync`。合并页面及同步状态入口需要分别验证兼容跳转。

- 检查教师和超级管理员可访问路径、长姓名、多角色、无资料、资料读取失败、离线、待提交和冲突状态。
- 在常用窗口及窄窗口检查标题重复、刷新和模块操作按钮遮挡；用实际点击和几何检测证明按钮可见、可用。
- 留下代表页面截图及逐页检查记录；使用现有主题和字体，实际渲染检查字形、行高和截断。
- 运行与账号、身份切换、导航、同步、更新及资料接口有关的检查；现有 `npm run test:desktop-layout` 基线已通过，但未覆盖固定账号栏，不能当作遮挡问题已修复的证据。

## 发布边界

纯桌面布局改动按桌面组件递增版本。个人资料接口或数据字段改动需要同时验证云端、小程序和存储代理兼容性，更新相应组件版本及发布证据。按项目流程完成测试、提交和推送 `gewu/master`，发布并验证 OSS 桌面更新。

只有适用端均有版本和运行证据时才能声明发布完成；存在外部平台或权限阻断时明确记录部分发布状态。保留工作区已有文档修改和未跟踪文件，不将其未经核查纳入本次发布。
