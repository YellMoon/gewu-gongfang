# 统一桌面端静默登记与离线确认草稿准入设计

**状态：架构边界仍有效；M16 仅是可销毁本地 PG17 的历史安全参考，不能再用来描述当前云端业务实现或发布状态。当前运行时与发布状态以[云端业务权威强制契约](2026-08-21-vnext-cloud-business-authority-architecture-contract.md)、[统一桌面在线登录修正](2026-08-23-unified-desktop-online-login-correction-design.md)和[`docs/release-version-matrix.md`](../../release-version-matrix.md)为准。**

## 1. 决策与范围

格物工坊只保留一种桌面端安装包。安装包、计算机或网络位置不决定用户权限；云端账户、角色、能力和数据范围才决定权限。新电脑上的首次登录必须在线完成账号验证；验证成功后，系统在云端静默登记设备、安装实例与账户关联。这里的“静默”是指不需要管理员、旧设备或所谓主机人工审批，不是跳过账号验证、设备私钥证明或审计。

离线不是重新登录通道。只有此前已在线建立、尚未过期且未被撤销的本地会话，才能在离线时继续使用受允许的本地功能并创建加密草稿。草稿不改变云端权威数据，也不能在恢复网络时自动提交；客户端必须展示影响与冲突，并由用户对每次提交明确确认。

本设计冻结未来替换身份登记与离线草稿边界所需的状态机、攻击面和测试合同。当前已新增 M16 的本地可销毁 PG17 命令验证：专用身份验证角色可签发断言，受限 writer 只可执行登记命令；它不修改现有 HTTP 登录、桌面构建、真实账号、真实设备、RDS 或发布流程。

因此，M16 当前不准入实现真实身份服务、设备私钥验证、离线草稿、HTTP 接线、RDS 或发布；此限制只约束该本地参考工件，不能否定已经由独立云端服务、桌面运行时和发布矩阵覆盖的当前实现。

它服从[云端业务权威架构强制契约](2026-08-21-vnext-cloud-business-authority-architecture-contract.md)：云端是适用业务数据、结构化题库文字、账户、权限、会话和任务状态的唯一写入权威；NAS 或受控存储代理只保存富媒体字节、导入原件、产物和备份。统一桌面端不恢复本地主机业务权威，也不形成两套安装包。

## 2. 已发现的旧路径：必须封存，不得局部复用

下列实现是旧“`primary-host` / `desktop-client` 双角色 + 人工设备审批”路线的证据，不是新架构的基础。未来切换前必须逐项建立封存或替换清单；在新成功路径中不得与其并行拼接，也不得把其本地 SQLite 状态当作云端登记的输入或权威。

| 旧路径类别 | 已定位的实现 | 与新架构的冲突 | 新路径处理原则 |
| --- | --- | --- | --- |
| 设备登记状态机 | `backend/src/services/desktopIdentityService.js` | 使用 `identity_verified_pending_approval`、`approved_pending_exchange`，并维护 `desktop_device_authorizations`。 | 新登记不得进入等待人工审批的状态，也不得读取旧授权行作为成功依据。 |
| HTTP 审批与主机路由 | `backend/src/routes/desktopIdentity.js`、`backend/src/routes/desktopIdentity.http.test.js` | 暴露 `/primary-host/*`，测试明确要求已验证访客等待主机审批。 | 新统一桌面注册命令不得调用、重定向或降级到这些路由。 |
| 桌面客户端登记 | `src/services/desktopIdentityClient.mjs`、`public/desktopIdentityVault.js` | 默认 `desktop-client`，并以 `approved_pending_exchange` 完成注册。 | 新客户端只接受统一 `desktop` 语义与新的在线登记结果。 |
| 构建与运行时角色 | `public/desktopBuildFlavor.js`、`public/runtimeConfig.js`、`public/preload.js`、`public/electron.js` | 以 `primary-host` 和 `desktop-client` 区分能力、IPC、监听和生命周期。 | 新安装包不以角色分叉；任何保留代码在切换前必须被显式隔离，不能成为新命令后备路径。 |
| 主机裁决、LAN 与恢复 UI | `public/primaryHost*.js`、`src/services/identityDeviceCenterPolicy.mjs`、`src/services/desktopAuthorityClient.mjs` | 把主机/本地 transport 作为正式命令裁决者。 | 新路径只向云端权威命令提交；本地仅保存加密草稿和缓存，不裁决正式写入。 |

本表不是删除授权。旧代码、历史审计和既有用户状态在后续迁移前必须保留以便诊断；但它们不得被包装成“兼容模式”而继续决定新登记、会话、权限或正式业务命令。

## 3. 未来唯一的在线静默登记状态机

### 3.1 前置条件

1. 桌面端已联网，并通过云端账号验证事件；该事件绑定预期受众、登录会话、一次性 nonce、过期时间和消费状态。
2. 新安装实例在本机生成不可导出的设备私钥；请求只上传公钥或其指纹及对服务端挑战的签名证明，绝不上传私钥。
3. 注册请求带独立的、规范化的幂等键，以及仅用于风险与审计的安装实例标识。设备名称、平台信息和展示标签不能单独作为身份或授权证据。

### 3.2 云端原子命令

云端未来应以单一、受审计的命令完成以下动作。对于首次登记，它验证账号事件未过期且未消费、验证挑战签名与幂等键/公钥/安装实例绑定，随后原子消费验证事件，创建或重用同一账户下的设备、安装实例和关联，建立短期在线会话，并写入必要的审计与撤销版本。

为使一次性验证与安全重放不矛盾，服务端必须先以“幂等键 + 账户 + 公钥指纹 + 安装实例 + 规范化逻辑请求哈希”查询既有登记。所有字段完全相同才进入受控 replay 分支：不重复创建设备，但仍要求新的在线验证与设备证明，才可取得新的会话结果。没有既有登记时，才校验并原子消费一次性验证事件。任一字段差异均为冲突，且零部分写入。会话机密不得保存在可重放回执中，也不得把历史 token 原样读回。

下列情况必须失败关闭，且不产生部分登记：同一公钥或安装实例绑定另一账户；同一幂等键对应不同账户/公钥/安装实例/挑战；已消费、过期或受众不匹配的验证事件；挑战签名无效；被撤销的设备或安装实例试图恢复会话；任何账户、设备或会话版本冲突。

成功后状态只可为“已在线登记并拥有短期在线会话”。不存在“等待主机审批”“等待旧设备确认”“主机自恢复优先”或由安装包类型决定的成功分支。

## 4. 离线会话与草稿的严格边界

### 4.1 可以离线做什么

离线入口只能验证本机已经持有的加密会话/租约：账户和设备绑定一致、未过期、未被本地已持久化的撤销版本否定、密钥材料可用。它不验证新账号密码、不创建新会话、不接受新设备登录，也不以旧 `desktop_device_authorizations`、浏览器缓存或旧 SQLite 行替代云端会话。离线端无法即时知道其断网后发生的远端撤销；这种未知撤销不把草稿误变为已提交命令。恢复网络时必须先刷新撤销/版本信息；若发现撤销或版本不再满足前提，云端拒绝提交并向用户展示原因。

符合条件时，桌面端可读取已缓存且本地允许的数据，并把用户操作封装为加密的 `awaiting_confirmation` 草稿。草稿必须账户、设备和会话分区；记录规范化命令摘要、影响预览输入、幂等键和最小版本前提，但不记录原始登录 token、账号验证码、设备私钥、手机号或不必要的业务明文。

### 4.2 恢复联网后的唯一提交流程

1. 客户端重新取得在线会话并获取当前云端版本/冲突信息。
2. 对每份待确认草稿展示受影响对象、可能冲突与不可自动合并原因。
3. 用户明确确认一次后，才调用云端权威命令；确认前、关闭窗口、重启应用或网络恢复本身都不得提交。
4. 每次提交复用该草稿的规范化幂等键。网络重试只能查询或重放同一云端结果，不能创建第二次正式命令。
5. 云端接受、拒绝或发现冲突后，客户端持久化非敏感结果状态；失败不得悄悄改写草稿内容或自动降级到本地主机、LAN 或旧 relay 成功路径。

所谓“仅允许继续使用未过期的本地会话”，准确含义是：已经完成过在线登录的用户，在网络不可用时可暂时解锁其本机、未过期且未被本地撤销信息否定的会话，并只形成草稿；它不允许离线重新登录，不把离线草稿变成云端已提交命令，也不授予额外权限。

## 5. 安全与隐私不变量

- 云端验证事件必须具有受众、nonce、有效期和一次性消费语义；客户端不得自行构造“已验证”声明。
- 设备证明必须由新设备私钥生成。公钥指纹相同但账户不同、安装实例不同但请求身份不一致，均必须失败关闭。
- 本地已收到设备、安装实例或会话撤销信息后，后续在线续期和离线草稿入口均必须被拒绝；未知的远端撤销在重连刷新时必须阻止草稿提交并提示用户。恢复只能由新的在线验证与登记流程完成。
- 日志、错误、草稿和回执只保留最小化的非敏感标识/哈希/代码。不得写入 token、密码、验证码、私钥、原始联系方式或不必要的业务明文。
- 本地缓存和草稿不是业务权威，也不是同步服务器；NAS 不参与账号、设备、会话、权限或草稿裁决。
- 设备登记服务于会话隔离、风险控制、撤销和审计，绝不把某一台电脑升级为业务主机或管理员审批者。

## 6. 实现前必须先通过的 synthetic TDD 合同

实现必须先用闭包拥有的虚构账户、虚构设备公钥和可销毁本地/PG17 测试边界建立以下失败测试；不得以真实账号、真实电脑、真实云数据库、D 盘旧数据、NAS、HTTP 发布或小程序替代。

| 场景 | 必须证明的结果 |
| --- | --- |
| 新设备在线验证成功 | 一次命令原子产生或重用设备、安装实例、关联和短期在线会话；没有审批状态。 |
| 精确重放 | 同一规范化请求不重复建记录，返回同一逻辑登记结果；不重放历史会话机密。 |
| 绑定冲突 | 跨账户公钥、安装实例或幂等键冲突失败关闭，零部分写入。 |
| 验证事件攻击 | 过期、错误受众、重复 nonce、已消费事件、错误签名均被拒绝。 |
| 离线入口 | 新设备或新账号离线登录被拒绝；过期、撤销或账户/设备不匹配的本地会话被拒绝。 |
| 草稿持久化 | 离线操作只生成加密 `awaiting_confirmation` 草稿；重启、恢复网络、后台重试均不提交。 |
| 确认与重试 | 明确确认后最多形成一次云端命令；网络重试只重放同一幂等结果；冲突和拒绝对用户可见。 |
| 旧路径隔离 | 新成功路径不访问审批状态、`primary-host` 路由、本地主机 transport 或旧授权表；旧路由不能把请求送入新成功路径。 |

每个未来测试还必须证明：调用者不能伪造账号/设备/会话声明；审计与错误不泄露机密；失败、回滚和并发下没有部分登记或自动提交；云端权威数据不因本地草稿而改变。

## 7. 重新开启实现的硬门槛

### 已交付的局部证据

M16 已在本地可销毁 PG17 中验证：断言只由专用身份验证角色签发；桌面公开边界只接受断言 ID 和幂等键，安全时间只取数据库事务时间；受限 writer 不能直接写表，只能执行登记命令；首次登记、精确重放、新断言复用同一结果、并发撤销、同一安装实例的不同账户隔离、过期/错误受众/重复 nonce/已消费断言、硬件证据不匹配，以及账户版本变化或撤销均失败关闭或返回同一逻辑结果。回执、审计或 outbox 的主键冲突会整体回滚。令牌、密码、私钥和 JWT 不写入 M16 表、回执、审计或 outbox。

这不是外部身份验证、设备证明或真实发布完成的证据，也不启用离线草稿。

在以下事项全部经独立设计、TDD 与权限审计确认之前，**M16 本地参考保持 no-go**；它不是对当前云端业务权威部署的全局状态结论：

1. 可在云端权威数据库中执行、但不授予任意表 DML 的命令级写入身份与登记命令能力；
2. 账户验证、设备私钥证明、会话签发/撤销与密钥轮换的完整接口契约；
3. 旧审批/主机/双构建路径的逐路由、逐服务、逐持久表封存和迁移方案；
4. 加密草稿的本地密钥、最小化字段、崩溃恢复、确认 UI 与冲突展示设计；
5. 桌面端、云端、NAS/存储代理和小程序的版本兼容矩阵，以及真实环境单独授权后的验证与发布计划。

在此之前，不得把现有旧审批流程说成新架构已经兼容，也不得宣称“任意电脑都可登录”意味着离线可以新登录。正确语义是：任意电脑都可安装同一桌面端；首次或重新建立会话必须在线完成账号验证和静默设备登记；之后仅在已有会话仍有效时可离线制作待用户确认的草稿。
