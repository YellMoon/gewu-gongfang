# 桌面人类身份、多角色、多设备与数据主机换机设计

日期：2026-07-17
状态：用户已批准混合身份方案，并确认固定超级管理员同时是老师、当前使用两台电脑且未来可能换机

## 替代关系

本设计扩展并部分取代 `2026-07-12-managed-desktop-sync-design.md` 中“管理员替设备选择任意真实账号后批准”的配对模型。旧设计保留设备秘密、服务端批准、可撤销凭证、同步前预览和主机/普通端配置隔离；以下行为被废止：

- 未验证申请人身份时仅凭设备信息申请；
- 审核员在待配对记录中任意选择另一个账号；
- 把 30 天 JWT 当作不可撤销的桌面身份；
- 只有权限管理页底部才存在审核入口；
- 用单一 `users.role` 表达一个人的全部身份；
- 固定超级管理员初始化时强制清空 `teacher_id`；
- 在普通设置页把一台电脑自行切换为数据主机。

## 目标

1. 桌面端先证明“谁在操作”，再决定“哪台设备可访问哪些数据”；设备信息本身永远不是人类身份证明。
2. 首次注册、新电脑、身份恢复和高风险异常使用微信扫码进入正式小程序，并由用户主动使用微信手机号能力确认本次桌面操作。
3. 已验证且已批准的电脑日常启动使用本地密码/PIN，后续可接入 Windows Hello；密码只解锁本机设备凭证，不成为可在任意电脑使用的云账号密码。
4. 同一个人可以同时拥有多个角色。固定超级管理员可同时拥有唯一老师角色并绑定唯一 `teacher_id`，不创建第二个用户或第二个老师档案。
5. 同一身份可拥有多台分别注册、分别批准、分别撤销的电脑；当前两台和未来换机都使用同一人类身份与角色授权。
6. “数据主机”是设备职责，不是用户角色。一个人可在数据主机和普通电脑上分别登录；同一租户同一时刻只有一台生效的主数据主机。
7. 数据主机有醒目的身份与设备审核中心、待审数量和可审计审批链，不再依赖隐藏在权限页底部的面板。
8. 计划换机和旧主机损坏两种恢复路径都可执行；云端不能仅凭手机号把任意电脑提升为权威数据主机。

## 非目标

- 不把阿里云变成最高权威业务数据库；云端只保存认证、设备、会话、控制面和中继所需最小数据。
- 不允许普通电脑直接写数据主机移动硬盘题库目录。
- 不取消离线编辑，也不取消同步前预览与用户确认。
- 不让本机密码替代微信手机号完成首次身份注册、换机或找回。
- 不把超级管理员权限永久混入老师数据范围；当前工作身份必须由服务端执行。
- 不允许两台数据主机同时领取或提交同一权威任务。

## 核心概念

### 人类身份、角色授权和业务主体

`users` 继续表示唯一人类认证身份。新增角色授权集合，而不是复制用户。固定超级管理员的同一身份同时拥有 `super_admin` 与 `teacher` 授权；老师授权引用唯一 `teacher_id`。当前数据主机、另一台普通电脑和未来新增电脑分别拥有设备授权，但都指向这个人类身份。

数据库新增 `user_role_grants`：

- `(user_id, role)` 唯一；
- 老师授权必须带 `subject_type='teacher'` 和唯一 `subject_id=teacher_id`；
- 学生授权必须带对应 `student_id`；
- 超级管理员授权只属于固定、已验证的规范身份；
- 授权包含状态、授予人、来源和撤销时间，全部变更写授权审计。

兼容期内 `users.role` 保存最高兼容角色，固定超级管理员仍为 `super_admin`；`users.teacher_id` 可以同时保存其真实老师绑定，不再被 `_enforceCanonicalSuperAdmin()` 清空。旧代码读取标量角色仍得到安全的最高角色，新代码通过角色授权集合决定可选工作身份。

### 当前工作身份

每个在线会话只有一个 `active_role`：

- 多角色账号首次默认老师工作台，之后默认最近使用的非特权角色；
- `active_role=teacher` 时，服务端只返回 `teacher_id` 对应的老师数据范围，即使该用户同时是超级管理员；
- 切换到 `super_admin` 必须重新输入本机密码/PIN，签发带近期提权时间的短会话；
- 设备审批、主机迁移、账号禁用和冲突处理要求 `active_role=super_admin` 且提权时间不超过 15 分钟；
- 老师与管理员缓存按 `{user_id, active_role, subject_id}` 分区，禁止串用。

小程序每次登录仍强制验证微信手机号。若一个正式身份有多个角色，小程序也由服务端返回可选角色并签发单一 `active_role` 会话；切换角色不得获得未授权角色。

### 设备身份与设备职责

新增 `desktop_device_authorizations` 作为耐久设备真相：

- `device_id` 全局唯一，绑定一个 `user_id` 和一个设备公钥指纹；
- 状态为 `pending/active/revoked/replaced/retired`；
- 保存批准者、批准来源设备、最近手机号核验时间、重新核验截止时间、凭证版本、最后在线时间和替换关系；
- 一个人可以有多条 `active` 设备授权，不限定为两台；每台可单独撤销，不影响同一人的其他设备；
- 同一设备不得改绑另一人。换人使用必须撤销、清除本机凭证并重新注册；
- `device_kind` 区分 `desktop-client` 与 `primary-host`。公开注册只能申请 `desktop-client`，不能自报主机职责。

`sync_devices` 继续作为本地权威主机的同步执行镜像，但 owner、active、trusted 和 role 必须来自已验证的设备授权或经过签名的主机迁移，不接受客户端自报。

## 桌面注册与登录流程

### 新电脑或首次注册

1. Electron 主进程生成设备密钥和稳定安装 ID；渲染进程只得到设备 ID、公钥指纹和展示名称。
2. Backend 创建 10 分钟一次性挑战，返回二维码和短码。二维码只含随机挑战标识，不含手机号、用户 ID、角色、设备秘密或主机密钥。
3. 用户用微信扫码进入正式小程序，查看设备名称、指纹摘要、申请时间和用途。
4. 用户主动点击“验证手机号并确认本次桌面登录”；小程序提交新的微信 `code + phoneCode`，Backend 交换真实 openid 和手机号并复用现有身份冲突规则。
5. Backend 将挑战固定到该已验证 `user_id`。审核员只能批准或拒绝这个声明人，接口不再接受任意 `userId`。
6. 新设备进入 `identity_verified_pending_approval`。审批必须来自另一台已激活设备，待审设备不能自批。
7. 批准后待审电脑用自己的私钥完成挑战证明，激活设备授权；用户设置本机密码/PIN并保存加密凭证。

同一个超级管理员可以在当前主机上批准自己已用微信证明身份的第二台电脑：微信手机号证明人、可信旧设备证明审批端、待审设备私钥证明目标设备，三者均写入审计。

### 已批准电脑的日常登录

1. 应用启动先显示身份门，不加载业务数据库页面、后台主机轮询或同步传输。
2. 用户输入本机密码/PIN；Electron 主进程使用 `scrypt` 派生密钥，结合 Windows `safeStorage` 解密设备私钥/刷新凭证。密码、派生密钥和私钥不写日志、不进入渲染持久存储。
3. 在线时主进程用设备私钥完成服务器挑战，获得最长 8 小时的 `desktop-session`，其中含 `sid/user_id/device_id/eligible_roles/active_role/auth_version/credential_version/auth_time`。
4. 离线时只允许使用加密保存的本地身份租约打开对应角色缓存和继续离线编辑，最长 72 小时；离线租约不能调用云端、主机端或同步写接口。
5. 上次微信手机号核验超过 30 天、账号权限变化、手机号换绑、设备风险异常或凭证版本失配时，必须重新扫码。
6. 同步仍需展示变更预览并由用户确认；同步另外要求在线有效桌面会话和有效设备授权。

### 本机密码与找回

- 本机密码不是服务端账号密码，不会在另一台电脑生效，也不上传明文或通用密码验证值。
- 凭证信封使用 `scrypt + AES-256-GCM` 加密，再由 `safeStorage` 保护；主进程限制失败次数并渐进延迟。
- 忘记本机密码时清除该设备的本地信封，通过微信手机号重新验证并由已有可信设备重新批准/恢复。
- 后续接入 Windows Hello 时只替换本地解锁因子，不改变手机号注册、设备批准和服务器会话规则。

## 可见的身份与设备审核中心

桌面端新增顶级“身份与设备”页面，而不是在 `PermissionManager` 底部附带一个面板：

- 数据主机和已授权超级管理员启动后显示待审角标与通知；
- 列表展示已验证申请人、脱敏手机号、角色集合、设备名称、设备 ID/公钥指纹摘要、申请时间和是否为本人新增设备；
- 不存在账号下拉选择器；批准载荷只含 challenge/authorization ID 和并发版本；
- 展示本人全部设备，允许重命名、撤销、标记丢失、查看最后在线和替换关系；
- 撤销某台设备立即递增凭证版本、撤销服务器会话并禁止新同步，但保留该电脑本地数据和待同步队列；
- 主机端与小程序超级管理员入口查询同一个 `/scheduling` Backend 控制面数据库；
- 普通管理员、老师工作身份和待审设备不能审批设备。

当前审批页允许管理员任意选择用户，这是已确认的安全缺陷。新接口和 UI 必须同时删除该能力；只改前端不合格。

## 当前数据主机引导

现有主机升级后不能因为尚无新桌面会话而陷入死锁。只提供一次受控引导：

1. 检测本机 `nodeRole=primary-host`、已有权威数据库和题库 authority binding，且尚无激活的主机设备授权。
2. 本机只显示“建立当前数据主机身份”，不开放业务页面或任意用户选择。
3. 固定超级管理员扫码验证规范手机号；本机物理确认后写入设备指纹、数据库实例摘要和题库 storeId 摘要。
4. 原子创建超级管理员角色授权、保留/绑定唯一 `teacher_id`、激活当前主机设备授权，并生成离线恢复包。
5. 引导成功后永久关闭；重复执行、非规范手机号、已有主机或 authority binding 不一致全部失败并留审计。

云端手机号不能单独证明主机权威；本地权威数据和题库绑定、物理确认、微信身份三者缺一不可。

## 数据主机计划换机

计划更换主机时采用不中断旧主机的两阶段迁移：

1. 新电脑先作为普通 `desktop-client` 完成微信身份验证、旧设备审批和本机密码设置。
2. 超级管理员在旧主机选择目标设备，进行近期提权并生成绑定目标公钥的 `host_transfer`。
3. 旧主机创建一致性数据库备份和配置清单；题库移动硬盘由用户物理连接到新主机，不经云端复制。
4. 新主机恢复备份，校验 SQLite、schema/version、附件、题库 `storeId/authority binding`、云连接和同步 dry-run。
5. 全部通过后才提交新一代 `primary_host_epoch`：新设备变为 `primary-host`、轮换主机密钥、旧设备变为 `retired`，云任务只定向新 generation。
6. 激活前失败时旧主机继续有效；激活后回退必须创建更高 generation 的反向迁移，不能同时恢复两个主机。

同一超级管理员在新旧两台电脑上的身份不变，老师档案和 `teacher_id` 不迁移、不复制，只是设备职责变化。

## 旧主机损坏时的紧急恢复

首次主机引导或每次成功迁移后生成新的离线恢复包。恢复同时要求：

- 固定超级管理员重新验证微信手机号；
- 提供未使用的离线恢复因子；
- 恢复最近一致性权威数据库备份并验证题库 authority binding；
- 新设备完成密钥证明；
- 云端确认上一主机失联且没有活跃迁移/任务租约。

恢复成功创建更高 `primary_host_epoch`，撤销旧主机设备和会话并轮换主机密钥。只有微信手机号、只有数据库副本或只有恢复包都不足以提升新主机；恢复包和旧主机同时丢失时进入人工灾难恢复，不自动放宽。

## Backend、Gateway 与本地主机边界

### `/scheduling` Backend

作为唯一桌面人类身份与设备控制面，负责微信手机号核验、挑战、角色授权、设备授权、短会话、撤销、审批、主机 generation 元数据和审计。它只保存业务主体 ID 映射，不成为学生、老师、课程、财务或题库权威数据库。

### Gateway

不再拥有另一套配对真相。旧公开配对 start/approve/exchange 路由返回 410 `DESKTOP_PAIRING_V1_REMOVED`，正式同步中继只接受 Backend 签发且可在线校验的设备会话/断言。兼容窗不得允许旧 Gateway 审核员继续任意选用户。

### 本地数据主机

继续保存全量权威业务数据、同步设备镜像、主机 generation、恢复收据和题库 authority binding。主机接收 Backend 控制面签名的设备/同步声明，但应用业务变更时仍执行本地用户、角色、`teacher_id`、设备、范围、同步确认和冲突检查。

## 数据表与状态机

新增或演进：

- `user_role_grants`：一人多角色与业务主体引用；
- `desktop_identity_challenges`：一次性手机号声明和设备审批状态；
- `desktop_device_authorizations`：耐久设备归属、指纹、版本与撤销；
- `desktop_sessions`：短时在线会话、当前工作身份与提权时间；
- `primary_host_epochs`：每租户唯一主机 generation；
- `host_recovery_factors`：只保存慢哈希，不保存恢复明文。

挑战状态依次为 `pending_phone`、`identity_verified_pending_approval`、`approved_pending_exchange` 和 `exchanged`。失败状态包括 `expired/rejected/conflict/cancelled`。

状态更新使用 `row_version` CAS；一次挑战只能绑定一个声明人和一个设备指纹。

## 安全不变量

1. 设备信息、短码或二维码本身不能证明人类身份。
2. 审核员不能把挑战改绑到另一个用户；声明人只来自本次微信手机号验证。
3. 待审设备不能批准自己；同一人只能从另一台已激活设备批准自己的新设备。
4. 一个用户可以有多台设备，但一台设备同一时刻只能属于一个用户。
5. 超级管理员和老师可以是同一用户；老师角色必须引用唯一 `teacher_id`，不能复制老师业务档案。
6. `active_role=teacher` 的会话必须执行老师范围，不能因 eligible roles 含超级管理员而获得全量数据。
7. 本机密码只解锁当前设备，不是跨设备身份凭证。
8. 设备撤销、用户停用、`auth_version` 或 `credential_version` 变化必须使现有会话失效。
9. 离线租约只能访问本机已分区缓存，不能同步、审批设备或执行主机写操作。
10. 同一租户只有一个激活的 `primary_host_epoch`；主机角色不能从客户端载荷或设置页自报。
11. 主机迁移必须先验证权威数据库、题库绑定和同步 dry-run；云端不得替代权威业务数据。
12. 密码、微信 code/phoneCode、设备私钥、恢复因子、JWT、主机密钥和完整请求体不得进入日志或审计。

## 迁移与兼容

- 先增加表和读取兼容，不删除旧列；把现有已批准用户转换为角色授权。
- 固定超级管理员创建 `super_admin` grant；若其手机号唯一匹配一个未删除老师档案，则经人工确认创建 `teacher` grant 并保留 `users.teacher_id`。不凭姓名猜测，不自动新建第二个老师。
- 旧 approved pairing 没有申请人微信证明，不能直接升级为新设备授权。当前数据主机走一次性 bootstrap；其他电脑升级后重新扫码，但保留本地数据和待同步队列。
- 新版启用前撤销旧 30 天桌面 JWT；旧客户端得到 `DESKTOP_IDENTITY_UPGRADE_REQUIRED`，不能回退到任意账号选择。
- Gateway 配对表只保留审计/回滚读取期，停止写入；兼容期结束后再做独立清理迁移。
- 所有数据库迁移部署前备份。回滚代码不删除已创建的角色、设备、会话、主机 generation 或审计记录。

## 验证与验收

### 数据与授权

- 迁移后固定超级管理员仍为唯一超级管理员，同时保留唯一 `teacher_id` 和两条有效角色 grant；
- 同一身份两台设备均可激活且互不覆盖；撤销一台不影响另一台；第三台换机也走同一规则；
- 老师工作身份只能看到本人数据，切换超级管理员前后服务端范围与缓存均变化；
- 非规范超级管理员、普通管理员、老师会话和待审设备不能审批设备或迁移主机。

### 登录、主机与同步

- 新设备不提交手机号/用户/角色，扫码后必须实际交换新的微信手机号凭证；
- 声明人固定，任意 `userId` 注入、二维码重放、跨设备秘密、过期、并发批准、换绑和自批均失败；
- 本机密码错误限速，密码与设备私钥不出现在文件、IPC 日志或渲染持久存储；
- Electron 重启需本机密码，在线短会话、72 小时离线租约、30 天手机号复核和撤销失效均有时间边界测试；
- 当前主机 bootstrap 不产生审批死锁且只能成功一次；
- 主机审核中心在真实 Electron 桌面和窄窗口可见，待审角标、空态、失败态和并发状态完整；
- 两台普通设备同步时仍需预览确认，设备、用户、当前角色和老师范围全链验证；
- 计划换机在激活前失败保持旧主机，成功后旧主机不能再 heartbeat、claim 或写题库；
- 紧急恢复缺少手机号、恢复因子、权威备份或题库绑定任一项均失败。

### 发布与最终验收

桌面身份改动影响小程序手机号确认、Backend、Gateway、本地主机和 OSS 客户端，必须进入当前目标的统一版本矩阵。顺序为兼容 Backend 数据迁移与双读、本地主机升级/bootstrap、小程序桌面确认入口、新桌面客户端与 OSS feed、最后关闭 Gateway V1。任一步未完成只能报告部分发布或受阻。

最终必须证明：同一手机号身份可在当前主机和另一台电脑分别登录，两台设备显示同一人、同一角色集合和同一 `teacher_id`；用户默认可进入老师工作台并经近期本机密码提权进入超级管理员工作台；新电脑或换机先微信验证再由可信旧设备批准；主机端有独立审核中心；任何时刻只有一个主数据主机。
