# 统一角色与数据范围权限设计

日期：2026-07-11
状态：已确认，待实施

## 目标

将现有互相割裂的桌面本地权限、小程序角色权限和邀请码授权，收敛为一套由权威服务端执行的身份与数据范围模型。系统只保留超级管理员、普通管理员、老师、学生以及审核前的待审核状态；桌面端、小程序和同步链路使用相同的权限判断。

本设计同时删除不生效的“菜单结构管理”页面，以及邀请者、邀请码授权、本地模块授权矩阵等旧权限体系。

## 不变约束

- 本地数据主机保存全量权威业务数据，云端只承担认证、中继、快照、小程序 API 和任务队列。
- 离线客户端变更必须经用户确认后同步，不得静默推送。
- 老师账号必须通过规范化手机号唯一匹配老师档案，并绑定唯一 `teacher_id`。
- 老师在桌面端和小程序端具有相同的业务能力和相同的数据范围。
- 题库不按老师归属隔离，但已确认写入主机题库盘的试题，只能由本地数据主机桌面端删除。

## 角色模型

### 超级管理员

- 角色标识：`super_admin`。
- 手机号 `13732250653` 固定识别为超级管理员；服务端必须再次校验，不能只依赖客户端角色字段。
- 拥有全量业务数据和全部业务操作。
- 独占用户审核、角色分类、老师绑定、普通管理员任命、停用与恢复用户的权限。
- 可在桌面端和小程序端执行上述管理操作。

### 普通管理员

- 角色标识：`admin`。
- 可查看和编辑全量业务数据，使用桌面端和小程序端全部普通业务功能。
- 不得审核用户、修改用户类型、绑定老师档案或任命管理员。
- 即使客户端显示或伪造审核入口，服务端也必须拒绝。

### 老师

- 角色标识：`teacher`。
- 审核通过的用户手机号必须唯一匹配 `teachers.phone`；成功后在用户记录中保存唯一 `teacher_id`。
- 手机号缺失、重复或匹配不到老师档案时，审核不能完成，并显示可处理的错误原因。
- 可使用桌面端与小程序端的全部普通业务功能，但非题库业务数据必须限定为自身范围。
- 课程、排课、课时费、学费、学生关系和机构收入等范围由课程的 `teacher_id` 推导。
- 老师自行输入且不能由课程推导的资产等数据，使用 `owner_user_id` 标记归属。
- 聚合统计必须先过滤明细再汇总，不能在全量汇总后仅隐藏界面行。

### 学生

- 角色标识：`student`。
- 保留现有本人关联数据的只读能力，以及现有明确允许的组卷、Word/PDF 导出等有限任务。
- 不得获得桌面全量数据访问能力。

### 待审核

- 新账号默认 `pending`，审核前不能读取业务数据或提交业务变更。
- 仅超级管理员可以将其分类为普通管理员、老师或学生。

## 数据范围与归属

每次请求构造不可由客户端覆盖的权限上下文：`user_id`、`role`、`teacher_id`、`device_id`、`is_primary_host` 和客户端类型。

- 超级管理员、普通管理员：普通业务数据范围为全量。
- 老师：普通业务数据范围为绑定的 `teacher_id`，并只下发该老师课程直接关联的学生和必要基础资料。
- 学生：数据范围为当前已绑定学生身份。
- 待审核或绑定异常：数据范围为空。

写入时服务端根据权限上下文覆盖或校验归属字段，不信任请求体中的 `teacher_id`、`owner_user_id`、角色或主机标识。跨老师关联、归属缺失或绑定不完整的数据默认拒绝，必要时形成管理员可见的审核记录。

业务记录逐步补充来源元数据：`owner_user_id`、`created_by_user_id`、`updated_by_user_id`、`source_device_id`、`source_operation_id`。已有记录通过课程和老师关系迁移；无法可靠推导的记录保持不可见并进入迁移报告，不猜测归属。

## 同步边界

### 主机下发

- 管理员设备可获取全量授权数据。
- 老师设备只获取绑定 `teacher_id` 的课程及其排课、关联学生、费用明细和本人输入数据。
- 学生设备只获取当前学生范围内的只读快照。
- 题库内容不按老师过滤，但按题目存储状态控制写入能力。

### 客户端回传

每条操作携带 `actor_user_id`、`actor_teacher_id`、`source_device_id`、`operation_id` 和基础版本。主机使用当前权威关系重新校验：

- 合法且无冲突：写入权威库，并记录创建及修改来源。
- 越权：拒绝，保留拒绝原因，不进入权威业务表。
- 版本冲突或归属不明：进入待审核队列，不自动覆盖。

客户端仍需在同步前获得用户确认。服务端授权令牌必须绑定用户、设备、范围和有效期。

## 题库特殊策略

题库试题没有老师归属，因此老师和管理员均拥有查看、录入、编辑、组卷和导出等题库业务能力；学生继续沿用有限能力。

题目必须区分：

- `local_draft`：仅存在于当前设备、尚未确认进入主机题库盘。当前设备用户可以增删改。
- `host_committed`：已确认进入本地数据主机管理的题库盘。

删除 `host_committed` 试题必须同时满足：请求来自本地数据主机、客户端类型为桌面端、经过服务端与题库存储服务双重校验。小程序、云中继、普通客户端，即使用户是超级管理员，也不能直接删除。

非主机端对已入库试题的修改以同步变更请求提交，由主机校验并落库；删除请求直接拒绝。界面隐藏按钮只是辅助，路由、同步服务和题库盘写入服务都必须执行相同硬检查。

## 管理界面

桌面端和小程序端提供一致的用户审核工作台：

- 待审核、超级管理员、普通管理员、老师、学生分类与筛选。
- 显示手机号、审核状态、角色、绑定 `teacher_id`、绑定老师、设备与最近同步状态。
- 仅超级管理员显示并可使用审核、角色调整、老师绑定和停用操作。
- 普通管理员可以查看状态，但操作控件不展示；直接调用接口也会被拒绝。
- 清晰处理加载、空列表、失败、手机号冲突、无匹配老师、重复匹配、已停用和保存中的状态。
- 删除旧邀请码、被邀请者和模块授权矩阵，不再展示实际不生效的配置。

“菜单结构管理”页面、导航项、页面类型、渲染分支和残留引用全部删除。

## 迁移与兼容

- 数据库迁移只新增字段或表，不破坏既有业务记录；迁移前使用项目现有备份机制生成可恢复快照。
- 现有 `admin` 用户保留普通管理员身份；`13732250653` 升级或固定为超级管理员。
- 现有 `teacher` 用户在手机号唯一匹配后绑定；不能唯一匹配的转为待审核。
- 现有 `student` 保留当前身份和绑定关系。
- `invited`、`invitee` 及其他旧角色转为待审核，不自动授予业务权限。
- 停止读取和写入 `permissions_data`、`invite_codes_geworks`；不主动删除浏览器中的旧键，以便代码回滚，但新版本不再使用。

## 安全与错误处理

- 所有权限结论均由服务端或本地主机可信边界得出；客户端仅用于呈现。
- 返回无权限时使用稳定错误码，避免泄露其他老师或学生的数据是否存在。
- 审核、角色变更、同步拒绝、题库盘删除全部写入审计日志。
- 超级管理员固定手机号、角色任命和题库盘删除属于高风险操作，必须有确认和明确结果反馈。

## 验证标准

- 单元测试覆盖角色能力、超级管理员固定识别、老师手机号唯一绑定、数据范围推导、先过滤后汇总和旧角色迁移。
- API 测试覆盖桌面端与小程序端审核、普通管理员越权拒绝、老师跨范围读写拒绝和待审核零权限。
- 同步测试覆盖老师范围下发、合法回传、伪造 `teacher_id`、跨老师关联、冲突队列和来源记录。
- 题库测试覆盖本地草稿增删改、主机桌面删除成功，以及小程序、云中继、非主机桌面删除拒绝。
- UI 在真实桌面运行时和小程序运行时验证超级管理员、普通管理员、老师、学生、待审核及异常绑定状态，并检查宽屏和窄屏布局、键盘焦点和无运行时错误。
- `npm test`、桌面生产构建、小程序类型检查及发布检查通过。

## 发布与回滚

- 按“身份模型 → 数据范围 → 同步校验 → 题库保护 → 管理界面”的顺序实施，每一步都有测试保护。
- 数据库迁移前保留快照；代码可按实施提交逐步回滚，字段保留不影响旧版本读取。
- 全部验证完成后提交并推送 `gewu/master`，自动递增桌面版本，构建 Windows 安装包，发布 OSS 更新 feed，恢复并验证 Node native 依赖。
