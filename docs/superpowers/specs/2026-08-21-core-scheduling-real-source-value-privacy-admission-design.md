# 核心排课真实旧库值语义与隐私准入设计

**状态：设计已冻结；真实旧库只读预检、真实影子导入、RDS 写入、切换与发布仍未获准。**

## 1. 目标与严格范围

本设计为格物工坊的云端业务权威迁移建立下一道门槛：在读取任何真实旧库行之前，先证明核心排课数据可以被稳定、最小化并且不泄露隐私地解释。它不改变“云端对适用业务数据拥有唯一写入权威、NAS 仅保存富媒体和备份”的总纲，也不改变统一桌面端的在线登记与离线确认草稿边界。

本批仅覆盖当前业务状态中的八类关系：机构/学校/上课地址、老师、学生、课程、课程默认收费与花名册、排课、排课级出勤与收费覆盖。目标关系仍是已验证的十张 `business` 表。题库和资产当前没有数据，故本批明确**不读取、不映射、不导入、不建立空行**；题目正文、富媒体、媒体路径、NAS 文件、会话、设备、旧授权和账号凭据也不在范围内。

这里的“逐条核验”不是逐个学生或排课人工审批。它是对固定关系、固定字段和自动化约束逐行运行同一套校验器，再只输出去标识化的汇总结果与不可逆哈希。

## 2. 当前状态与历史变更的解释

真实旧库在获准的只读快照时刻的**当前有效状态**是本批唯一候选迁移输入。课程、排课、出勤和费用的历史编辑、删除和重排，只要已经反映在该时刻的当前状态中，就随该状态进入影子核验；不会另外把变更日志再执行一遍，也不会由迁移器猜测“如何重放”历史操作。

已报告的 3013 条本地变更是必须纳入核对的来源线索，而不是一个可以直接入库的命令包：

1. 若某项变更的结果已体现在获准快照的当前业务表中，它由当前行的稳定 ID、版本/更新时间、关联和汇总核对覆盖。
2. 若某项仅存在于独立本地草稿、同步日志或冲突记录而未反映在当前业务状态中，它不得作为裸行导入，也不得静默重放；仍受 [本地草稿准入边界](2026-08-21-legacy-local-draft-intake-admission-design.md) 约束，未来只能成为用户确认的幂等云端命令。
3. 用户已确认的删除课程遗留排课只可按不可变例外隔离：不创建虚假学生、不替换为课程默认花名册、不删除源行。后来正确关联学生并重新排出的课程/排课，若位于当前有效状态中，按普通关系和金额/出勤规则核验。

## 3. 真实源的最小只读边界

每次真实预检必须由用户针对一个明确源根与一个明确 SQLite 快照单独授权。执行器解析真实路径后只接受授权根内的单一数据库文件；打开方式必须是只读、查询专用、无扩展加载、无附加数据库、无动态 SQL 的单一只读事务。

允许的查询是固定 SQL 清单：仅八类获准关系及其已知明细的列读取，以及已冻结的 SQLite 结构元数据读取。禁止路径发现、目录枚举、写事务、`ATTACH`、备份、导出、样本展示、任意表扫描、题库/资产/NAS 读取和网络上传。

预检在读取前后分别计算同一源文件身份和快照指纹。两次值必须完全一致；任何变化、锁定异常、WAL/SHM 不能组成一致快照、未批准表访问或读取错误都返回固定失败代码并且不进入影子写入。报告不得出现源路径、原始行、原始稳定 ID、联系方式、备注、姓名、手机号、微信标识、学生/老师姓名或课程文本。

## 4. 自动值语义合同

预检器必须针对每行应用同一套冻结规则；不能修复、填补、猜测或静默降级。

| 数据面 | 必须自动证明 | 失败处理 |
| --- | --- | --- |
| 机构、学校、上课地址 | 稳定 ID、租户归属、名称/状态/软删除/时间字段的可解析性；学校与地址只引用同租户的已知父记录。 | 隔离，不创建替代父记录。 |
| 老师与学生 | 稳定 ID、同租户关系、生命周期、时间字段和允许的业务枚举；老师/学生没有旧 `user_id` 不是失败，也不得伪造账号关联。 | 隔离，不创建云端账户。 |
| 课程 | 机构与老师属于同一租户；课程状态、时间、时长、计费设置和默认花名册可解释。历史 `room_id` 仅保存为显示/遗留快照，不能猜测为有效房间外键。 | 隔离，不猜测房间或老师。 |
| 课程默认花名册及收费 | 每个学生存在且同租户；金额以精确十进制文本解析；出勤状态不被当作课程级事实。 | 隔离，不以零金额替代。 |
| 排课 | 开始/结束墙钟时间按 `Asia/Shanghai` 解析后转换为有限 UTC instant；结束必须晚于开始；课程、状态、软删除、显示地点和已存汇总金额可解释。 | 隔离，不以客户端当前时区重写时间。 |
| 排课级覆盖 | 明确覆盖整体优先于课程默认花名册；学生同租户；正常出勤可参与费用计算，取消和请假仍保存为事实但不计入旧费用公式。 | 隔离，不把覆盖与默认花名册拼接。 |
| 金额与汇总 | 课程默认/排课覆盖的学费和老师课时费均按精确 decimal 计算；目标有效花名册的计算结果必须与源保存的排课汇总一致。 | `RECONCILIATION_MISMATCH` 隔离。 |
| 已批准遗留例外 | 例外行必须同时匹配获批快照、固定关系、固定稳定 ID 集合和冻结行哈希。 | 仅产生 `USER_DECLARED_OBSOLETE_LEGACY_SCHEDULE` 隔离记录；任何近似行仍失败关闭。 |

来源字段中的布尔、整数、时间和金额必须在解析前保留原始值用于仅内存的规范化哈希；解析后只有规范化的结构化值可进入影子目标。`NULL`、空字符串、无限数、越界整数、未知枚举、跨租户引用、重复稳定键和不可解析时间/金额都不得被“清洗”成成功行。

## 5. 隐私、日志与报告

老师/学生的联系方式、家长字段、微信标识、自由备注和可能包含个人信息的课程/排课文本属于受限输入。它们只在一次受控进程的私有内存中完成字段验证或最小化目标映射；不得写入普通日志、测试输出、错误文本、迁移账本、审计、outbox、汇总报告或通用查询投影。

预检输出仅可包含：关系名称、总数、成功/隔离/例外计数、固定错误码的计数、去标识化键集合哈希、逻辑行哈希、源前后指纹是否相等、批准映射/DDL/mapper 版本哈希和影子目标身份哈希。需要保留可复核原始证据时，必须先另行批准加密密封工件、最小读取者、密钥生命周期和保留期限；当前设计不创建这种工件。

## 6. 影子准入与可恢复性

只有预检全程成功、源前后指纹一致、结构/值语义映射版本匹配且无未批准隔离项时，才能把规范化数据提交给已有的**可销毁、本地** PostgreSQL 影子目标。每个批次绑定下列不可变值：源前/后快照哈希、源结构/目录哈希、mapper 版本集、business DDL manifest 哈希、影子目标身份、用户授权记录的哈希和去标识化批次请求哈希。

影子写入顺序固定为：机构/学校/上课地址，老师/学生，课程，课程默认花名册，排课，排课级覆盖。提交后必须由独立只读事务重读十张目标表并比较行数、键集合、逻辑哈希、租户外键、有效花名册来源、出勤分布和每节课的费用汇总。完全相同的批次仅可只读重放；任一源/映射/目标哈希差异均冲突。

失败、隔离、回滚或终端事务不确定时，影子数据库组必须被销毁，不能继续使用。这里的“可恢复”仅指可销毁影子环境回到零数据；它**不**授权删除任何真实云端已写业务行，也不承诺未来切换后的通用回滚。

## 7. 通过门槛与明确禁止项

进入真实旧库只读预检实现前，必须先完成：

1. 该设计的实施计划与 synthetic TDD；
2. 用户对单一只读源根和快照时点的明确授权；
3. 已审阅的固定 SQL 清单、路径 realpath 约束、源前后指纹算法与去标识化报告格式；
4. 八类关系的字段映射、租户解析、状态/时间/金额/出勤计算和 18 条已批准例外的独立测试；
5. 对所有失败、精确重放、目标篡改、源变化、隐私泄露、事务不确定和影子销毁路径的可重复测试。

在上述门槛通过前，禁止真实 SQLite 行读取、真实 PostgreSQL/RDS 写入、API 接线、NAS 写入、桌面发布、切换或对用户宣称迁移完成。即使预检和影子导入未来完成，真实云端切换仍须经独立的备份、恢复、版本兼容、多端确认、用户可见影响预览与发布验证。
