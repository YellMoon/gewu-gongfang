# 格物工坊云端权威 vNext 架构设计

日期：2026-08-13

状态：已获用户方向确认，待书面规格复核

适用项目：`scheduling-system`（格物工坊）

## 1. 决策摘要

格物工坊采用“重写基础架构层、保留业务逻辑”的迁移路线，不继续深化“指定本地数据主机是唯一业务权威”的实现，也不把整个业务项目推倒重写。

目标架构固定为：

- 阿里云是账户、设备、角色、权限、业务数据、题库结构化内容、任务状态和审计记录的唯一权威来源。
- 桌面端统一为一种安装包；超级管理员能力由云端账户角色、具体 capability、数据 scope、可信设备状态和近期重新认证共同决定，不绑定某一台数据主机电脑。
- 微信小程序继续以只读和有限写入为主，所有权限由云端逐请求校验。
- NAS 或独立存储代理只负责题库大文件、Word/PDF 产物、文件校验和备份，不裁决用户、权限或业务事务。
- 移动硬盘优先作为 NAS 的离线备份；若 DX4600 的容器目录隔离能力不满足要求，则存储代理先运行在受控 Windows/Linux 设备上，NAS 仅提供存储目标。
- 普通桌面允许离线查看授权缓存和编辑本地草稿；联网后必须由用户查看影响预览并确认，才可提交云端，禁止静默推送。
- 当前桌面端、权威 SQLite、IndexedDB、本地草稿、题库盘和附件必须完整盘点、备份、校验和迁移；新架构验收完成前不得删除或覆盖旧数据。

## 2. 目标、成功标准和非目标

### 2.1 目标

1. 保留学生、老师、课程、排课、收费、课耗、资产、题库、公式、组卷、Word/PDF 导出等现有业务逻辑和真实数据。
2. 重写身份、设备信任、授权、通信、数据持久化、离线同步和存储任务边界。
3. 将原本“桌面端 → 云中继 → 数据主机 → 回执/投影”的业务写链路改为“客户端 → 云端授权事务 → 审计/outbox → 事件通知”。
4. 建立可重复、可中断续传、可核对、可回滚的数据迁移和注入流程。
5. 在同一安装包中支持普通用户、老师、学生和超级管理员，不以安装 flavor 提升权限。
6. 让题库元数据与文件存储解耦；NAS 暂时不可用时，业务库保持一致，并明确显示文件待处理、缺失或不可用状态。

### 2.2 成功标准

- 云端数据库是适用业务表唯一可写权威；旧数据主机不再参与用户、权限或业务命令裁决。
- 旧业务 ID 在无冲突时原样保留；所有 ID 变化均有迁移账本映射。
- 每张业务表都有数量、主键集合、规范化行哈希和外键校验报告。
- 每个题库文件都有来源、目标、大小和 SHA-256 校验结果；旧文件在观察期内保留。
- 所有旧记录均得到 `migrated`、`archived`、`quarantined` 或 `intentionally_excluded` 的明确结果，不允许静默丢弃。
- 同一设备登录多个账户时，本地分区、PIN、缓存、草稿、outbox 和离线许可证互相隔离。
- 客户端伪造 `user_id`、`teacher_id`、`student_id`、`device_id`、`owner_id` 或 scope 不会改变服务端授权结果。
- 超级管理员可在任一已授权桌面安装中使用审核能力；高危操作要求在线、近期重新认证、具体 capability 和审计原因。
- 离线草稿不会静默同步；越权或 scope 已收缩的草稿可查看、导出或放弃，但不能提交。
- 桌面端、微信小程序、云端、存储代理和备份链路均有当前版本的自动化与真实运行证据后，才允许声明统一发布完成。

### 2.3 非目标

- 不在第一阶段重新设计现有业务页面视觉样式。
- 不在第一阶段重写排课算法、财务计算、题库编辑器或公式转换引擎。
- 不把 NAS 的 SMB 目录或 SQLite 文件直接开放给各桌面端并发写入。
- 不把 RAID 当作备份，也不因 NAS 上线而取消移动硬盘离线副本。
- 不进行长期新旧双写；双写只允许存在于受控迁移演练，并且不得成为正式稳态架构。
- 不迁移旧 access token、refresh token、session、验证码、主机私钥、过期 challenge 或可重建缓存为新系统的有效凭证。

## 3. 现有工作树的复用与停止边界

参考工作树：`codex/account-permission-device-trust`。该工作树中的用户、档案、设备和权限设计具有较高复用价值，但其最终裁决仍绑定本地数据主机。

### 3.1 直接复用或适配复用

- `users.id` 作为不可替换账户主体。
- `teachers.id`、`students.id` 作为不可替换业务档案主体；允许存在尚未绑定账户的业务档案。
- 账户、基础角色、档案绑定、能力、数据范围和家庭关系分别建模。
- `trusted_devices`、`device_installations`、`account_device_links` 和账户本地分区四层设备模型。
- 每次安装生成 Ed25519 密钥；私钥只保存在操作系统保护存储，服务端仅保存公钥。
- 一个物理设备可关联多个账户，每个账户拥有独立本地数据分区。
- 在线短会话、初始化会话和离线许可证分离。
- capability 目录、页面访问清单、业务路由访问清单和 action 级服务端鉴权。
- AccessContext 的角色、档案绑定、capability、scope、版本和哈希结构。
- 设备克隆检测、风险事件、分层撤销和审计思路。
- 本地授权快照、离线草稿、outbox、冲突隔离和用户确认提交机制。
- 幂等键、row version、事务审计、outbox event 和 WebSocket 通知机制。
- 学校规范名/别名、账户—档案匹配、重复档案预览合并、家庭邀请和资产 owner 的业务建模。

### 3.2 必须替换

- `primary_host_epochs` 作为业务权威选举机制。
- `host_receipts` 作为账户、权限、档案或业务事务最终结果。
- `primary-host` 安装 flavor 和主机专属审核中心。
- 首次注册、设备登记、账户初始化或权限刷新必须等待数据主机在线的要求。
- 主机 command worker、主机领取业务命令、主机发布业务 projection 的主链路。
- LAN WebSocket 作为业务提交候选传输，以及主机发现、主机心跳对业务可用性的影响。
- 云端仅保存控制面镜像、不得保存全量业务数据的旧约束。
- `host_committed` 等以主机硬盘写入为核心的题库状态语义。

### 3.3 暂停策略

- 保留该工作树的提交、未提交文件和测试输出，不 reset、clean、删除或发布。
- 新 vNext 实施从稳定基线建立独立分支；通过提交级或文件级选择性移植复用代码。
- 不直接把该工作树整体合并后再反向拆除主机权威机制。
- 每次移植必须证明不依赖 host epoch、host receipt、主机专属 runtime 或主机业务库。

## 4. 目标系统边界

```text
统一桌面端 ─┐
             ├─ HTTPS / WebSocket ─→ 阿里云业务服务 ─→ 云端权威数据库
微信小程序 ─┘                               │
                                            ├─ outbox / 任务队列
                                            └─ 审计 / 备份 / 监控
                                                     ↑
存储代理 ── 主动出站连接、短时签名任务、幂等回执 ─────┘
   │
   ├─ NAS 题库文件、导入原件、Word/PDF 产物
   └─ 移动硬盘离线备份
```

### 4.1 云端业务服务

负责：

- 认证、账户、设备、公钥和会话。
- 角色、档案绑定、capability、scope、家庭关系和审核。
- 学生、老师、课程、排课、收费、课耗、资产等业务事务。
- 题库结构化内容、版本、审核、文件对象索引和存储状态。
- 幂等、并发版本、审计、outbox、任务调度和通知。
- 授权快照和离线许可证签发、撤销与版本管理。

### 4.2 统一桌面端

负责：

- 在线业务 UI、账户切换和权限驱动导航。
- 每账户独立加密本地分区。
- 授权缓存、离线草稿、待提交 outbox 和冲突/隔离记录。
- 用户确认后的同步提交。
- 通过正式 API 申请题库文件、导入、组卷和导出任务。

桌面端不得：

- 直接写 NAS、主机移动硬盘或云数据库。
- 依据本地角色标签自行提升权限。
- 把硬件指纹当作认证凭证。
- 在退出或切换账户后继续保留上一账户的 AccessContext 或数据连接。

### 4.3 微信小程序

继续维持 surface 限制：

- 可读取本人或明确授权 scope 内的数据。
- 可执行财务个人资产导入、题库选题组卷、Word/PDF 导出等列入 allow-list 的有限写入。
- 不直接修改核心教务表、题库基础数据、用户角色或设备权限。
- 即使账户具有 `super_admin`，小程序也只获得小程序 surface 允许的 capability。

### 4.4 存储代理

负责：

- 主动连接云端领取任务；不要求路由器开放公网入站端口。
- 按对象 ID 和不可变版本写入题库文件。
- 计算并回报文件大小、SHA-256、媒体类型和存储位置摘要。
- 生成 Word/PDF、打包导入原件、执行 NAS → 移动硬盘备份。
- 上报介质在线、容量、只读、校验失败和备份结果。

存储代理不得：

- 直接创建用户、授予角色或修改业务 scope。
- 接受客户端提交的任意宿主机路径。
- 访问 NAS 上未显式授权的目录。
- 将 NAS 管理员密码、云端长期主密钥或 Docker socket 暴露给业务容器。

## 5. 用户、档案和权限模型

### 5.1 稳定主体

- `users`：可登录的人类账户。
- `teachers`：教师业务档案。
- `students`：学生业务档案。
- `profile_bindings`：账户与档案的活动/历史绑定。
- `role_grants`：基础角色标签及有效期。
- `capability_overrides`：在基础角色能力组合上的明确增减。
- `data_scope_grants`：可操作的档案、学校、家庭或资源范围。

账户 ID、教师 ID 和学生 ID 不互相替代。姓名、手机号、微信号和学校名称均不得作为数据库主键。

### 5.2 基础角色

正式基础角色固定为：

- `super_admin`
- `teacher`
- `student`
- 无正式角色时解析为 `visitor`

旧 `admin` 不继续作为含糊的运行时角色。迁移时逐账户预览并转换为明确角色、capability 和 scope；未完成选择的旧管理员保持受限状态。

### 5.3 capability 与 scope

角色只提供默认能力组合；每个页面动作和 API 使用具体 capability，例如：

- `student.read` / `student.write`
- `schedule.read` / `schedule.write`
- `payment.read` / `payment.write` / `payment.export`
- `asset.personal.read` / `asset.personal.write` / `asset.personal.export`
- `question.content.read` / `question.content.write` / `question.import` / `question.export`
- `question.taxonomy.manage` / `question.audit`
- `user.review` / `access.manage` / `device.revoke`

scope 决定数据范围，例如指定 `teacher_id`、`student_ids`、`school_ids`、`household_id` 或资源 owner。服务端必须从已验证会话和当前授权版本解析主体及 scope，覆盖或拒绝客户端自报 ID。

### 5.4 超级管理员

超级管理员不再绑定数据主机设备。审核中心开放必须同时满足：

1. 活动 `super_admin` 角色；
2. 当前安装和 account-device link 有效；
3. 在线正式会话有效；
4. 对应具体 capability 有效；
5. 高危操作完成近期重新认证；
6. 提交原因、row version、idempotency key，并写审计。

## 6. 设备与会话模型

### 6.1 四层设备模型

1. `trusted_devices`：稳定物理设备环境摘要和风险状态。
2. `device_installations`：当前软件安装实例、公钥和凭证版本。
3. `account_device_links`：账户是否允许在该设备使用。
4. `account_local_partitions`：当前账户在本机的加密缓存、草稿和 outbox。

硬件指纹仅作为风险证据，不能单独签发 session、link、scope 或离线许可证。

### 6.2 多账户隔离

同一安装可登录多个账户，但每个账户必须具有独立：

- 数据密钥和 PIN/解锁材料；
- SQLite/IndexedDB 分区；
- 授权快照和缓存版本；
- 草稿、outbox 和隔离区；
- 离线许可证。

账户切换必须先关闭旧分区、清空内存 AccessContext、取消订阅和请求缓存，再打开新分区。

### 6.3 会话与离线许可

- access token：建议 15 分钟。
- 在线桌面会话：建议不超过 8 小时，可撤销。
- 初始化会话：只允许下载并提交授权快照、建立本地分区，不允许访问正式业务 API。
- 离线许可证：最长 30 天，绑定 user、device、installation、partition、capability hash、scope hash、snapshot hash 和版本。
- 近期重新认证：高危操作建议 5～15 分钟内有效。

离线许可证只允许读取已缓存授权数据和编辑草稿；同步、审核、权限修改、题库正式写入、正式导出、设备处置和备份恢复必须在线。

## 7. 通信与事务模型

### 7.1 正式写入链路

```text
请求
→ 验证 token/session/device/installation/link
→ 加载当前角色、档案绑定、capability、scope 和版本
→ 校验 row_version、idempotency key 和业务不变量
→ 单数据库事务写业务记录
→ 写 audit event
→ 写 outbox event
→ 提交事务并返回 committed version
→ WebSocket 通知其他客户端刷新
```

WebSocket 只负责降低延迟；断线后客户端通过版本游标、HTTP 拉取或 durable event 恢复，不得以 socket 消息作为唯一成功凭证。

### 7.2 离线提交

离线编辑写入本地分区中的 draft/outbox，并记录：

- 业务对象、基础版本和字段差异；
- 创建账户、设备、安装和本地时间；
- 预期 capability/scope hash；
- 附件引用和本地哈希；
- 是否已由用户确认。

联网后先调用预检 API，显示新增、修改、删除、冲突、越权、文件任务和不可逆影响。只有用户确认后才提交。scope 收缩或权限撤销的草稿进入 quarantine，可查看/导出/放弃，但不可同步。

### 7.3 兼容过渡

- 旧 API 在迁移窗口内通过 adapter 读取新服务，但不得形成第二写入真相。
- 无法安全适配的旧写路由返回 410，并包含 replacement route 和 migration version。
- 新旧协议使用 feature flag 分阶段切换；正式切换后旧写路径保持关闭。

## 8. 题库和文件状态机

### 8.1 云端保存

- 题目结构化内容、答案、解析、选项和小题。
- 分类、章节、知识点、模型点和版本。
- 审核、来源、导入批次和操作审计。
- 文件对象 ID、对象版本、哈希、大小、媒体类型和存储状态。
- 组卷/导出任务参数、输入快照和产物索引。

### 8.2 NAS/存储节点保存

- 图片、Word 原件、PDF、MathType/OLE 原始对象。
- 导入包、不可变任务输入和导出产物。
- 备份包和恢复验证所需文件。

### 8.3 文件状态

建议状态机：

```text
pending_upload
→ storage_queued
→ stored
→ verified

任一步可进入 missing / quarantined / failed_retryable

删除：delete_pending → deleted
```

业务事务和文件任务使用 saga/outbox 协调：业务记录提交后可以显示“文件处理中”，但只有存储代理回报哈希一致后才显示 `verified`。失败可重复领取，任务必须幂等，不得重复创建逻辑文件版本。

### 8.4 DX4600 部署门槛

在将存储代理部署进 DX4600 Docker 前，必须实机证明：

- 能把一个独立目录显式挂载给容器；
- 容器不能访问其他共享/个人/系统目录；
- 不需要特权模式和 Docker socket；
- 重启后挂载和只读/读写边界保持；
- 局域网和本机小文件/大文件性能满足题库工作负载；
- 断网、磁盘只读、空间不足和容器重启均可恢复。

若任一硬门槛失败，存储代理部署在受控 Windows/Linux 设备，通过 NAS 提供的有限目录访问文件；总体云端权威架构不变。

## 9. 数据迁移与注入设计

### 9.1 原则

- 先盘点、再备份、再影子导入，最后才允许切换。
- 迁移复制数据，不移动或覆盖原数据。
- 原始数据全部保留；只有语义明确的数据进入新运行库。
- 无法自动判断的记录进入 quarantine，不进行猜测性合并。
- 所有迁移操作幂等且写 migration ledger。
- 正式迁移工具默认只读来源；任何清理必须在观察期后单独授权。

### 9.2 数据来源

至少盘点：

- 当前权威/桌面 SQLite 及其 WAL/SHM 状态。
- Electron userData 内 IndexedDB、SQLite、LocalStorage 和应用配置。
- 本地账户 vault、设备公钥和可证明私钥持有状态；私钥本身不上传。
- 草稿、outbox、冲突和未完成导入。
- 移动硬盘题库目录、附件、导入原件和导出产物。
- NAS 当前备份目录及版本。
- 云 Backend/Gateway 中现有账户、角色、设备、镜像、队列和审计。
- 小程序仍保留的本地缓存版本和待处理任务引用。

### 9.3 迁移包

每个来源生成不可变、加密迁移包：

```text
migration-bundle/
  manifest.json
  source/                 # 原始数据库只读副本和导出元信息
  business/               # 规范化 NDJSON/批量数据
  files/                  # 文件清单或受控复制内容
  offline/                # 草稿、outbox、冲突
  archive/                # 旧控制面和不再生效的数据
  checksums/sha256sums.json
  reports/inventory.json
  reports/migration-ledger.json
  reports/unresolved.json
```

`manifest.json` 记录来源版本、schema 版本、导出时间、表数量、主键范围、文件数量/大小/哈希、未提交草稿数量、悬空引用和迁移批次。报告与日志不得保存密码、token、私钥、完整手机号或不必要的真实本地路径。

### 9.4 分类规则

| 类别 | 处理方式 |
|---|---|
| 学生、老师、课程、排课、收费、课耗、资产 | 保留稳定 ID，规范化后注入云端业务库 |
| 题目结构化内容、分类、知识点、版本 | 保留 ID/版本，注入云端题库库 |
| 题库附件、导入原件、Word/PDF | 先复制到临时导入区，双端哈希一致后注册对象 |
| 未提交草稿/outbox | 注入对应账户本地分区的“待确认迁移”区，不自动提交 |
| 用户、角色、档案绑定、scope | 按证据和迁移规则转换，冲突进入人工处置 |
| 旧设备授权 | 只有用户重新认证且原安装能证明私钥持有时迁移为 active link |
| 旧 session/token/challenge | 归档或明确排除，不注入为有效凭证 |
| host epoch、host heartbeat、主机密钥 | 归档，不进入新运行时 |
| 可从云端重建的缓存 | 记录数量和哈希后归档/排除，不作为权威数据导入 |

### 9.5 导入顺序

1. schema version、租户/authority 和基础字典。
2. 学校、机构、房间、分类等基础实体。
3. 用户、验证联系方式和外部身份映射。
4. 老师、学生和其他业务档案。
5. 角色、档案绑定、capability、scope 和家庭关系。
6. 课程、排课、报名、收费、课耗和资产。
7. 题库结构化内容、分类关系和导入批次。
8. 文件对象清单、NAS 文件复制和哈希验证。
9. 审计、历史关系和需要保留的业务事件。
10. 每账户本地授权快照、缓存和待确认草稿注入。

每条记录写入：来源类型/ID、目标类型/ID、来源哈希、目标哈希、状态、冲突码和迁移批次。

### 9.6 身份和档案匹配

自动匹配证据优先级：

1. 已验证且规范化的手机号；
2. 已验证的微信/OpenID/UnionID 等 provider 证据；
3. 已存在稳定 user ID 或显式旧外键；
4. 旧 teacher/student 与账户的确定性绑定。

姓名、学校、昵称和手工微信号仅作人工参考，不得自动合并。多个确定性候选、重复档案、跨类型绑定或悬空引用必须进入预览式人工处置。

### 9.7 设备迁移

- 私钥不离开原设备。
- 旧安装通过服务器 nonce 签名证明持有原私钥，并要求账户重新登录。
- 证明通过后创建/恢复 installation 和 account-device link；证明失败视为新安装。
- 旧设备授权记录无法证明当前私钥持有时不得直接迁移为 active。
- 复制 userData 到不同设备必须触发风险阻断或重新登记。

### 9.8 题库文件注入

```text
旧移动硬盘/现有目录
→ 只读扫描和 SHA-256
→ 复制到 NAS 临时导入区
→ NAS 重新计算 SHA-256
→ 对比大小、哈希和对象版本
→ 云端注册文件对象并标记 verified
→ 原文件保持不变直到观察期结束
```

发现孤儿附件、同 ID 不同哈希、路径碰撞或缺失文件时进入 quarantine；不得用“最后修改时间较新”自动覆盖。

## 10. 迁移验证

### 10.1 机器验证

- 表级记录数量。
- 主键集合差异。
- 规范化行哈希。
- 外键和唯一性。
- 金额、课时、资产余额等聚合不变量。
- 题目、附件、公式和知识点关系数量。
- 文件大小和 SHA-256。
- 草稿/outbox 数量和账户归属。
- 所有来源记录的 migration ledger 终态。

### 10.2 业务验证

- 随机及定向抽取学生完整排课、缴费、课耗历史。
- 随机老师的课程、学生范围和收入/资产记录。
- 超级管理员、老师、学生、visitor 的页面/API 权限矩阵。
- 同机多账户隔离、账户切换和离线解锁。
- 离线草稿预检、确认、冲突和 quarantine。
- 题库导入、编辑、公式、组卷、Word/PDF 生成和附件读取。
- NAS 不在线、文件缺失、哈希错误、任务重试和备份恢复。
- 小程序只读、有限写入、无权限和离线状态。

### 10.3 验收门槛

以下任一项未满足均不得正式切换：

- 业务表或文件存在未解释差异。
- P0 迁移冲突未解决。
- 原始备份未通过只读恢复验证。
- 旧写路径仍可能形成第二权威来源。
- 设备撤销、权限收缩或账户隔离可被绕过。
- 题库文件状态与真实文件不一致。
- 回滚演练无法恢复旧系统或无法保留新系统增量。

## 11. 切换和回滚

### 11.1 切换流程

1. 完成至少一次全量影子迁移和一次从空库恢复演练。
2. 发布兼容客户端，但保持旧权威写路径。
3. 进入切换窗口，旧端转只读并禁止新的正式业务写入。
4. 对旧数据库和题库文件创建最终备份与哈希清单。
5. 导出并注入第一次影子迁移后的增量。
6. 执行全量差异、聚合和文件校验。
7. 切换云端 feature flag，使云端成为唯一写权威。
8. 新桌面登录、设备证明、建立账户分区并下载授权快照。
9. 旧草稿进入“待确认迁移”列表，由用户逐批确认。
10. 观察健康、错误、审计、队列和存储任务后逐步开放写能力。

### 11.2 回滚

回滚不进行猜测性反向同步：

- 立即停止新系统写入并保留云端数据库、审计和 outbox。
- 恢复切换前验证过的旧数据库和旧版本应用。
- 将切换后云端新增/修改数据导出为独立补偿包。
- 旧系统优先只读恢复；需要临时写入必须明确授权并重新确定下次增量边界。
- 修复后从原始备份和补偿包重新执行迁移。

旧软件、旧数据库、题库源文件和迁移包建议保留 30～90 天观察期；期满后的清理需要单独备份和用户授权。

## 12. 实施顺序

### 阶段 0：冻结与取证

- 暂停 `codex/account-permission-device-trust` 的主机权威深化。
- 保存工作树状态、提交、未提交文件清单和可复用模块清单。
- 建立 vNext 分支和 feature flags，不改生产数据。

### 阶段 1：盘点器与迁移框架

- 实现只读数据盘点器、迁移包、哈希、migration ledger 和恢复验证。
- 对当前真实桌面数据、权威 SQLite、题库盘和云控制面生成脱敏盘点报告。
- 先证明全部数据可导出和重放，再修改正式写路径。

### 阶段 2：云端 vNext schema

- 建立云端完整业务 schema、增量迁移、事务、审计、outbox 和备份恢复。
- 保持现有业务 ID；适配 SQLite → 云端数据库的类型、唯一性和事务差异。
- 建立影子导入环境，不连接生产客户端写入。

### 阶段 3：账户、档案、权限和设备

- 选择性移植工作树的用户/档案、capability/scope、trusted device、installation、account link、本地分区和离线许可设计。
- 把最终签发者从 host receipt 改为云端事务和云端签名上下文。
- 实现统一桌面登录、超级管理员近期提权和服务端逐请求鉴权。

### 阶段 4：业务 repository/API 适配

- 为学生、老师、课程、排课、收费、课耗和资产建立稳定 repository 接口。
- 现有业务逻辑调用新 repository，不在 UI 中直接感知数据库位置。
- 旧写 API 逐条适配或返回 410。

### 阶段 5：桌面离线层

- 每账户独立加密分区、授权快照、缓存、草稿、outbox 和 quarantine。
- 用户确认同步、row version 冲突、scope 收缩和撤销即时失效。
- 统一安装包按权限挂载管理员审核中心。

### 阶段 6：题库和存储代理

- 题库结构化内容迁入云端。
- 实现文件对象状态机、存储任务、代理回执、Word/PDF 任务和 NAS → 移动硬盘备份。
- 独立验证 DX4600；必要时使用 Windows/Linux 存储代理。

### 阶段 7：小程序与多端契约

- 小程序改用云端权威 API，维持 surface 级有限写入。
- 覆盖管理员/学生等适用角色和全部注册页面的真实状态。
- 接口、权限和数据结构变更进入统一版本矩阵。

### 阶段 8：影子迁移和真实验收

- 全量、增量、断点续传、冲突、文件校验和恢复演练。
- 真实打包 Electron、开发版小程序、云端和存储代理端到端验收。
- 验证旧系统只读、回滚补偿包和数据不丢失。

### 阶段 9：正式切换与观察

- 执行备份、冻结、最终增量、校验和 feature flag 切换。
- 发布统一桌面 OSS feed、云端服务和适用小程序版本。
- 验证 NAS/移动硬盘备份与恢复。
- 观察期结束前不删除旧数据和旧安装。

## 13. 测试与发布策略

- 单元测试：权限目录、scope、会话、设备证明、迁移转换、文件状态机。
- HTTP 合同测试：必须从正式 app 启动并穿过真实鉴权中间件。
- 数据迁移测试：从多版旧 schema、WAL 状态和中断点重复执行。
- E2E：统一桌面两个独立 userData、小程序、云端、存储代理和临时 NAS 目录。
- 安装包测试：真实 Electron 安装产物，不以源码浏览器测试替代。
- 灾难测试：云端数据库恢复、NAS 离线、存储任务重复、哈希错误、磁盘空间不足、断网和设备撤销。
- 发布前为阿里云数据库/代码、旧本地数据库、题库文件和迁移包分别创建备份并验证可读性。
- 其他电脑桌面仅通过 OSS feed 更新；微信上传、阿里云部署、存储代理升级和本地数据迁移均需独立回执。
- 任一适用端受阻时状态为“部分发布”或“受阻”，不得声明统一发布完成。

## 14. 主要风险与控制

| 风险 | 控制 |
|---|---|
| 旧 schema 复杂、历史表重复 | 先做数据字典和 migration ledger，禁止整库盲拷贝 |
| 账户与老师/学生档案误合并 | 只使用确定性已验证证据自动绑定；其余人工预览 |
| 离线修改覆盖云端 | row version、预检、用户确认、冲突/quarantine |
| 云端事务成功但 NAS 文件失败 | outbox/saga、明确文件状态、幂等重试和哈希验证 |
| DX4600 权限能力不足 | 存储代理可部署到独立受控设备，NAS 退化为存储目标 |
| 设备 userData 被复制 | 安装私钥证明、设备锚风险证据、账户重新认证和撤销 |
| 切换后需要回滚 | 旧端只读、最终快照、云端增量补偿包、恢复演练 |
| 云端成为单点 | 数据库备份/PITR、健康监控、服务回滚和只读降级 |
| 重写时遗漏业务规则 | 保留业务服务和断言；逐 repository 适配，不重写领域算法 |

## 15. 需要持续遵守的硬规则

1. 在迁移验证通过前不删除、移动或覆盖真实桌面数据库、题库盘和 NAS 备份。
2. 不将未验证的缓存副本提升为权威数据。
3. 不允许客户端自报身份、角色、owner 或 scope 成为授权依据。
4. 不允许离线草稿静默提交。
5. 不允许 NAS/Docker/存储代理获得业务权限裁决能力。
6. 不允许 WebSocket 成为唯一送达或成功证明。
7. 不允许长期双写或隐式回退到旧主机权威路径。
8. 每次 schema 或迁移修改必须幂等、可恢复、有账本、有备份。
9. 每次完成声明前必须执行对应的测试、构建、迁移或发布验证。
10. 新架构的第一项实现必须是只读盘点与可恢复迁移框架，而不是删除旧代码或迁移正式数据。
