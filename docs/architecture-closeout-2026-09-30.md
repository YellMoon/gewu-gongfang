## A2：真实登录已验证，断网发现实际缺陷

必要性：受控网络和预验证账户不能证明首次真实认证或实际断网体验。

用户在本机独立测试安装实例完成真实认证，软件静默登记设备，无人工放行。
用户报告另一台电脑桌面版本 8.10.0，已登录且能看到本机通过原始 UI 在线创建的
临时地址。用户不在机器旁，使用向日葵；按用户授权采用独立的定时 Wi-Fi 恢复脚本。
脚本只临时控制已保存连接的自动连接模式，恢复计时器先启动；连接及原设置已恢复。

真实 Wi-Fi 断开时，虚拟网卡让 navigator.onLine/Electron 在线提示仍为真。
原始页面保存遇到网络失败后，草稿被错误标成在线，恢复联网后两条临时更改未经确认
自动提交。实际云端读回证实此缺陷，不将它归为验收脚本问题。

修复限于既有链路：云端 fetch 失败的观测结果传给单条及批量本地草稿；原生加密
outbox 保留明确的 createdOffline=true，即便系统报告在线。随后成功的网络请求只
恢复新编辑的在线判定，不解除既有离线草稿的确认要求。REST、数据库、权限及其他端
协议不变。针对性回归执行实际缓存捕获方法、原生 outbox 与自动同步计划，覆盖重启、
整批确认要求、在线恢复和合并后仍保留离线标记；修复前红灯、修复后通过。

自动版本判定为桌面补丁 8.10.0 → 8.10.1。针对性测试和 TypeScript 检查通过。
完整 npm 生命周期首次停在历史 NAS 版本断言；更新批准清单到 8.8.4，并保留对未批准
8.8.5 的拒绝后，发布检查与剩余生命周期命令续跑通过。不能称为一次成功的 npm test。

当前状态：桌面补丁发布进行中；A2 尚未声明完成。最终只补这一个真实断网
闭环、一次确认后的云端读回和一个两电脑版本冲突。课程/地址依赖次序沿用已通过的
真实 outbox/REST 集成证据，不在每个业务页面重做相同断网、登录或全部 CRUD 组合。
