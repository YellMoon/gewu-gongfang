# 财务发布时发现的运行环境问题

本轮在功能测试通过后，继续通过真实部署和打包后复测发现并处理了两个独立问题。发布证据以 `output/personal-finance-integration-20261008/release-outcome.json` 为准。

## 专用邮箱的收件通道

已经注册的专用地址为 `gewu-bills-20261008-0801d4@agentmail.to`。同一凭据从本机读取 API 返回 200，从阿里云返回 CloudFront 的 HTML 403；这不是应用层密钥错误，未据此更换密钥或重新注册邮箱。

[AgentMail 官方 IMAP 文档](https://docs.agentmail.to/imap-smtp) 提供 `imap.agentmail.to:993` 的 TLS 收件方式。云端实际 TLS 登录与只读 INBOX 检查成功，因此新增服务端 `CLOUD_BILL_MAIL_TRANSPORT=imap` 配置。连接使用 EXAMINE 和 PEEK，保留所有者绑定；附件按 UIDVALIDITY、UID 和 MIME part 定位，邮箱重建后旧附件标识失效。大小、连接及整次检查超时有明确限制，凭据不会返回终端。

邮箱列表读取和合成附件测试不等于真实银行账单投递验证；尚未收到真实账单时不得宣称已验证真实投递和所有银行版式。

独立复核发现整次检查超时后迟到下载仍可能启动附件解析，新增回归先复现解析次数 1（预期 0），再通过取消检查和下载流销毁修复。8 项 IMAP 回归通过；独立夹具另验证迟到锁只释放一次、阻塞下载被销毁及迟到解析不会触发下一附件。

## 打包后的 Node 原生依赖恢复

桌面 Electron 安装包 ABI 检查通过后，旧 `npm rebuild` 恢复流程虽然也通过 ABI 137 的单条 SQL 检查，真实题库测试却稳定触发 `RemoveEnvironmentCleanupHook` 的 `env != nullptr` 断言。该故障发生在 Statement 垃圾回收，区别于前次已确认的旧 Node 24.15 Windows TCP/libuv 崩溃。

[Node 官方问题 65262](https://github.com/nodejs/node/issues/65262) 描述 ObjectWrap 头文件清理钩子与运行时之间的兼容性问题，[问题 65195](https://github.com/nodejs/node/issues/65195) 描述相关清理钩子生命周期缺陷。本机保持修复了 TCP 问题的 Node 24.21.0 运行时；在相同运行时下，使用官方 Node 24.15.0 的 ABI 137 头文件重新编译 backend 插件后，原先崩溃的真实题库测试通过。

`npm run rebuild:node` 现在清除继承的 Electron 构建参数和可绕过目标版本的 nodedir，分别重建根目录和 backend 的 SQLite 插件。在 Windows Node 24.19 及后续 24.x 环境中，使用已经验证的兼容头文件从源编译；不降级运行时。重建后同时执行 ABI、Statement GC 和真实题库测试。`dist:win` 在构建或打包失败时也执行恢复，避免仅在成功路径恢复。此兼容策略在更换运行时或移除上游问题的限制前需要重新验证。

## 课表内容与背景色对齐

用户连续反馈指出前一版课表不仅卡片没有按桌面端对齐，整体布局仍是大卡片列表，额外学生筛选、日期总结和节数占用了空间。仅卡片内容/颜色通过不能代表整个课表完成。本次最终要求以桌面实际 `TwoWeeksView` 为准：两排每排七天，按真实时间定位课程，顶部只上一周、本周、下一周，移除小程序额外学生筛选、日/周切换、周区间总结、每日节数。保留云端权限范围、上海日期导航和横屏支持。

背景色沿用桌面按课程上课地点分配的 24 色算法及缺地点默认色，文字色使用同一亮度计算。共同算法迁至 `shared/courseColors.js`，原桌面 TypeScript 接口保留。云端在同一租户快照中生成 `calendar_color`，只给已经授权的课程返回派生色，随即剔除完整配色基准；学生或教师只看到部分课程时，不再因本地重新排序而改变同一门课的颜色。真实 PostgreSQL 回归覆盖租户、删除标记、子集颜色一致和隐藏基准不外泄。

状态样式以桌面实际最终静态 JSX 为准：桌面随后对拖拽样式的赋值覆盖了状态函数的边框及透明度。本轮没有修改桌面该行为，也没有在小程序自行增加绿色侧条、状态文字、取消透明度或白底。实际组件回归和新 H5 截图分别验证内容、颜色和呈现；H5 fixture 不代表手机原生运行已验证。

实际浏览器继续检出 H5 同时启用横纵滚动时横向被默认样式隐藏，以及底部导航遮挡 50 px 可视高度。最终双轴样式与仅 H5 的页面高度修正已在管理员、教师、学生、家属范围下检查，11 张新网格截图见页面记录。小程序构建来源校验同步涵盖 `shared/`，共享配色、日期或财务代码变化后，旧编译产物不能继续作为有效构建证据。

随后用户指出横屏仍需拖动才能看到七天，固定 140 px 列宽不能照搬到手机横屏。最终横屏两排各七列自适应屏幕，竖屏保留 140 px 列与横向滚动；课卡水平内边距在横屏适当收紧，字号及时间定位不变。最终七天截图中实际 `clientWidth=scrollWidth=829`，周一至周日全部在屏内，普通八字课名和完整起止时间均无截断。此前固定列宽的横屏截图只保留为被纠正的历史记录。

桌面、云端、小程序补丁分别为 8.14.1、8.16.1、8.9.1；NAS 仍为 8.9.1，接口和存储协议保持本轮版本矩阵中的兼容关系。正式发布状态以运行时回执为准。
