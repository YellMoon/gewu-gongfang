### P1 统一账户停用后小程序旧票据仍保留权限

位置：[miniappCloudAccountRepository.js](C:/Users/83423/.openclaw/workspace/scheduling-system/cloud-business-api/src/miniappCloudAccountRepository.js:78)、[miniappCloudAccountService.js](C:/Users/83423/.openclaw/workspace/scheduling-system/cloud-business-api/src/miniappCloudAccountService.js:92)。

应在每次授权时核验统一账户、权威、会话和撤销版本；业务层角色不能自行维持已撤销的控制面权限。这项问题需要补充停用、撤销和旧票据重放的跨端契约测试。

### P1 桌面草稿未按当前账号隔离

位置：[desktopAuthorityRuntime.js](C:/Users/83423/.openclaw/workspace/scheduling-system/public/desktopAuthorityRuntime.js:511)、[browserDatabase.ts](C:/Users/83423/.openclaw/workspace/scheduling-system/src/services/browserDatabase.ts:206)、[desktopSyncController.mjs](C:/Users/83423/.openclaw/workspace/scheduling-system/src/services/desktopSyncController.mjs:79)。

草稿持久化了 `draftScope`，但运行时的读取、删除、重置和提交没有按当前账号校验该标记。账号 A 留下未提交草稿后切换到 B，B 的空数据投影仍被叠加 A 的学生数据；自动同步随后使用 B 的令牌发送 A 的草稿。云端仍会按 B 的权限校验请求，但本地跨账号数据可见和错误凭证发送已复现，具有误提交风险。

### P1 HTTP 故障期间的离线编辑绕过整体确认

位置：[desktopIdentityClient.mjs](C:/Users/83423/.openclaw/workspace/scheduling-system/src/services/desktopIdentityClient.mjs:306)、[desktopAuthorityRuntime.js](C:/Users/83423/.openclaw/workspace/scheduling-system/public/desktopAuthorityRuntime.js:292)、[DesktopIdentityGate.tsx](C:/Users/83423/.openclaw/workspace/scheduling-system/src/components/DesktopIdentityGate.tsx:379)。

HTTP 502、503、504 会使身份门进入离线模式，但请求函数在识别这些状态前已将 `cloudTransportUnavailable` 清为 false。电脑网络仍在线时，新草稿因此标成 `createdOffline=false`。完整模拟链路为：503 → 离线解锁 → 编辑 → 云恢复 → 自动同步完成，全程没有整体确认。这违反项目明确的离线提交约束。

应使用统一的云端可用状态及离线会话状态决定草稿来源，并覆盖 HTTP 故障后编辑、恢复和确认的全链测试。

### P1 正常登录后手工新增题目报错

应通过现有统一会话读取接口获取身份，保留原生草稿证明校验，不应恢复令牌的旧持久化方式。

### P1 云端写成功但响应丢失后桌面重试误报冲突

位置：[desktopCloudBusinessDraft.mjs](C:/Users/83423/.openclaw/workspace/scheduling-system/src/services/desktopCloudBusinessDraft.mjs:323)、[desktopIdentityClient.mjs](C:/Users/83423/.openclaw/workspace/scheduling-system/src/services/desktopIdentityClient.mjs:1071)。

本地生成了 `commandId` 和 `payloadHash`，普通业务 REST 写入却没有传递这些幂等标识。模拟房间更新已在云端提交、响应随后 ECONNRESET：重试旧版本令牌得到冲突，草稿进入 conflict。创建房间也会在重试时撞上名称唯一约束。该复现没有产生重复房间，但已成功事务被标记失败，并暂停后续自动同步。

应使云端持久化命令收据并支持查询、重放相同结果；响应不确定时应先确认命令结果，不能直接当作未提交重做。

## 后续修复的问题

### P2 题库分类并发更新可能覆盖修改并形成循环

位置：[分类更新 SQL](C:/Users/83423/.openclaw/workspace/scheduling-system/cloud-business-api/sql/20260824-question-taxonomy-authority.sql:67)、[分类节点更新 SQL](C:/Users/83423/.openclaw/workspace/scheduling-system/cloud-business-api/sql/20260824-question-taxonomy-authority.sql:123)、[分类删除 SQL](C:/Users/83423/.openclaw/workspace/scheduling-system/cloud-business-api/sql/20260906-question-taxonomy-version-fence.sql:53)。

函数先 SELECT 校验版本和树结构，再执行不含版本条件的 UPDATE，没有将校验和写入锁在同一并发边界。两条请求使用同一版本基线更新分类时，都返回 committed，第二次覆盖第一次。并发将 A 移到 B 下、B 移到 A 下也都成功，最终形成 A ↔ B 的循环；最新删除函数的 UNION ALL 递归在该数据上运行到 statement_timeout，返回 SQLSTATE 57014。

独立 PostgreSQL 17 夹具已确认当前迁移目录中这些函数的最后定义及实际 pg_get_functiondef。应提供原子的版本校验、同一分类体系的树变更锁和递归循环防护；还需检查已有数据是否包含环。

### P2 小程序导出重试产生第二个云任务

位置：[question-paper 页面](C:/Users/83423/.openclaw/workspace/scheduling-system/miniapp/src/pages/question-paper/index.tsx:431)、[paperExportTaskRepository.js](C:/Users/83423/.openclaw/workspace/scheduling-system/cloud-business-api/src/paperExportTaskRepository.js:113)。

未确认草稿重试应复用原始完整请求和幂等键；已确认失败后主动重新导出才使用新键。

### P2 NAS 慢响应同时阻塞任务和心跳

位置：[cloudClient.js](C:/Users/83423/.openclaw/workspace/scheduling-system/storage-agent/src/cloudClient.js:120)、[runtime.js](C:/Users/83423/.openclaw/workspace/scheduling-system/storage-agent/src/runtime.js:29)。

请求和正文解析没有总体截止时间，运行循环又串行等待心跳和任务。HTTP 200 后正文持续慢传时，单次任务可长期占住整个循环。模拟推进到 901 秒后请求仍在等待、心跳次数为 0，停止标志也无法结束该等待。任务租约默认 300 秒；运行时回执超过 900 秒后，会阻断要求新鲜回执的导入。

应对请求到正文消费设置总体超时，并避免业务请求阻塞心跳；仅依赖底层 socket 空闲超时不足以覆盖持续慢传。

应校准场景与真实权限、绑定本次源码和角色的截图证据。不能通过放开学生课程权限来迎合错误的清单。此次未声称当前微信全部页面或实际字形已通过视觉验收。
